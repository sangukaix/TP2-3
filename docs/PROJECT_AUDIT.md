## 2. 이번 점검에서 적용한 개선

- 소개 화면과 대시보드를 React `lazy`/`Suspense`로 분리해 첫 화면에서 대시보드 전체 코드를 받지 않게 했다.
- 원본 ZIP·CSV 파싱을 `ai_server/app/raw_data_repository.py`로 분리하고 파일 지문 기반 LRU 캐시를 적용했다.
- 원본이 바뀌면 자동으로 캐시를 무효화하고, `data/raw` 파일은 수정하지 않는다.
- Backend와 AI Server 응답에 GZip 압축을 적용하고, 키가 제거된 VWorld GeoJSON을 24시간 로컬 캐시해 큰 경계의 반복 다운로드를 줄였다.
- 운영체제 환경변수가 `.env`보다 우선하도록 설정 로딩 순서를 바로잡았다.
- 미지원 지역에 개발용 시연 수치를 표시하던 경로를 제거하고 명확한 빈 상태를 추가했다.
- 지역 변경·검색 중 이전 지역 카드와 그래프가 잠깐 남지 않도록 로딩 상태를 분리했다.
- 지역별 Word 파일명을 선택 지역명으로 생성하도록 고쳤다.

## 3. 성능·품질 확인값

동일 PC의 로컬 함수 호출 기준이며 네트워크·디스크 상태에 따라 달라질 수 있다.

| 항목 | 개선 전 | 개선 후 |
| --- | ---: | ---: |
| 지역 대시보드 첫 계산 | 약 2.67초 | 약 0.13초 |
| 대시보드 후 snapshot 계산 | 약 5.69초 | 약 0.34초 |
| 캐시된 대시보드 재계산 | 약 0.15초 | 약 0.05초 |
| Frontend 초기 단일 JS | 약 814KB | 소개 화면 6KB 미만 + 공통 약 193KB, 대시보드 지연 로딩 약 612KB |
| VWorld 시도 GeoJSON | 약 21.7MB | 약 2.1MB |
| VWorld 전국 시군구 GeoJSON | 약 36.1MB | 서버 캐시 약 2.7MB, 브라우저 서울 응답 약 24KB |
| 지도 서버 재시작 후 캐시 응답 | 원격 API 재호출 약 20초 이상 | 시도+서울 시군구 약 0.66초 |

Frontend lint와 production build, Agent 오케스트레이터 단위 테스트를 통과했다. 대시보드 지연 로딩 chunk는 아직 약 612KB이므로 다음 최적화에서는 지도·보고서 모달·문서 다운로드 UI를 추가 분리한다.

## 4. 다음 개발 우선순위

1. `data/processed` 정규화 파이프라인과 `region_code + year_month` 검증을 자동화한다.
2. MySQL schema·적재·일반 Dashboard API를 구현하고 원본 직접 읽기는 수집/검증 단계로 이동한다.
3. 공통 24~36개월 이상 지역을 확보한 뒤 seasonal-naive와 ML 후보를 시간순으로 비교한다.
4. 공식 문서·사례 RAG를 지역별로 확대하고 source URL·게시일·적용 조건을 검수한다.
5. 지도 캐시 만료·VWorld 장애 시 대체 경계 제공 방안과 시도별 응답 시간을 운영 환경에서 관찰한다.
6. 로그인, 보고서 저장·피드백, Nginx 배포와 정상·오류 경로 통합 테스트를 완료한다.
7. MySQL 서비스·전용 계정 설정 후 전국 `mysql_load_bundle`을 실제 적재하고, 171개 지역의 전국 비교 snapshot API를 통합 테스트한다.
