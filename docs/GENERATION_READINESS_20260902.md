# 강남구 기획안 생성 전 점검 — 2026-09-02

## 결론

강남구 생성 테스트를 위한 데이터·서버·모델 연결은 확인했다. 후보 비교와 근거/실행 검수를 보강했다.
실제 유료 기획안 생성은 아직 호출하지 않았으므로 최종 문장 품질·독창성·집행 가능성을 검증 완료했다고 주장하지 않는다.
기존 팀원 작업을 되돌리지 않았고 TP2-3만 수정했다.

## 생성 흐름과 이번 변경

```text
사용자: 강남구 + 예산·일정·시설/인력·필수 조건·첨부
  ├─ 로컬 원자료 → 검증된 관측값
  ├─ MySQL → 동일 기간 peer 비교 + 원본 출처
  └─ 저장 ML 모델 → 자연추세·오차·실행 후보 기간
           ↓
  [1 Evidence / OpenAI] 지역 정책·기존 사업·공간 조건·공식 관광 API
  [2 Case Scout / OpenAI] 타 지역 운영 원리·비용·성과·실패 조건
           ↓  실제 웹 검색 수행/조회 URL 확인
  [3 Transferability / Qwen] 서로 다른 사업 후보 2~3개
      지역 적합성·차별점·확보 조건·예산·측정·중단 기준 비교
      → 하나 선택 + 다른 후보 제외 이유
           ↓
  [4 Planner / Gemma] 하나의 실행안 + 5단계 일정·산출물
           ↓
  Python: 출처 ID·후보 참조·단계 검사
  [5 Reviewer / OpenAI] 근거·실행·예산·새로움·조건 충족 독립 검수
      ├─ 82점 이상 + critical/major 없음 → 검수 통과
      └─ 미달 → 기존 초안과 피드백으로 한 번 수정 → 재검수
           ↓
  검수 상태 + planning_decision(후보 비교) + 출처 + ML을 저장
  React 미리보기에서 보완점/선택 이유 확인 → 챗봇 수정 → 사용자 저장
  기존 편집형 12장 PPT / Word 출력 경로 유지
```

- 새 모델 단계는 추가하지 않았다. 기존 적합성 단계에 후보 비교 계약을 강화했다.
- 로컬 입력+출력 예산이 설정 문맥보다 크면 근거를 자르지 않고 Hybrid의 OpenAI 폴백을 사용한다. 긴 기획 단계가 반드시 개인 노트북에서 실행되는 것은 아니다.
- Ollama에 `num_predict`, `num_ctx`를 전달하고 실제 사용량을 기록한다. 잘린 출력/잘못된 JSON은 정상 응답으로 처리하지 않는다.
- `local_only`에서 OpenAI 폴백이 발생하던 경로를 막았다. Provider를 바꿀 때 잘못된 모델 태그를 재사용하지 않는다.
- 필수 검색에는 실제 Web Search 실행을 요구한다. 공식 도메인처럼 보이는 조작 URL도 조회 기록에 없으면 채택하지 않는다. 단, URL 일치가 문장 내용의 사실성까지 보장하지는 않는다.
- 중요한 오류가 남으면 ‘검토용 초안’으로 표시한다. 챗봇 수정 후에는 이전 승인 배지를 유지하지 않는다.
- 통신 실패로 빈 조사 결과를 받았을 때 다음 생성에도 6시간 재사용되던 캐시 경로를 수정했다.

## 기간·성과 해석

- 2026.09.02, 마지막 관측 2026.07일 때 내부 모델은 8월부터 계산하지만 실행 후보는 **9~11월 / 9~다음 해 2월**이다.
- 11월은 마지막 관측으로부터 4개월 후이므로 3개월 사업이라도 탐색 전망을 포함한다. ‘사업기간 3개월 = 전체 검증 완료’가 아니다.
- 현재 모델은 기존 이력의 자연추세만 예측한다. ‘사업을 해서 매출이 정확히 N% 늘어난다’는 인과효과 모델이 아니다.
- 사업 성과는 명시된 가정/목표와 평가 설계로 분리한다. 실제 효과 추정에는 사업 전후 결과·비교 집단 등 추가 관측이 필요하다.
- 월간 지표만으로 특정 골목·시간대·연령의 원인을 단정하지 않는다. 현장 확인 가설과 측정 절차를 기획에 넣는다.

## 남은 조건

1. 공식 사이트 `jeonnam.go.kr`, `evaluation.go.kr`, `jeonju.go.kr`는 사용자 승인 후 개별 추가 완료. 전체 `go.kr` 범위는 허용하지 않는다. 승인 전 제외됐던 강진 반값여행·야간관광 도시·전주 야간관광 예산 사례를 포함해 6건이 후보 입력에 사용 가능하다.
2. RAG 문서가 0건이다. 현재 검수 JSONL은 이미 모두 후보 입력에 직접 포함되므로 이를 RAG에 중복 색인하는 것만으로 새 지식이 생기지는 않는다. 다음 보강은 강남 기존 사업·결산·운영 조건과 비교 도시의 실제 평가 문서를 검수해 색인하는 일이다.
3. 최종 테스트 생성 후 제목만 다른 쿠폰/홍보인지, 강남구 병목에 맞는 작동 원리인지, 담당자·공간·예산·일정·중단 조건이 실제로 확인 가능한지 사람이 다시 점검해야 한다.
