# 후보 하나의 이용 흐름 실험 (2026-09-08)

## 범위

사용자의 후속 진행 요청에 따라 D-107의 동결 입력에서 근거 본문은 유지하고 시스템 지시와 최종 과제/Schema만 좁혔다. 후보 하나의 대상→신청→이용/결제→증빙 흐름을 담당자·행동·산출물로 작성하게 한다. 상세 예산·측정 설계·후보 간 선정·Gemma 본문은 이번 과제에서 제외했다. 따라서 이전 전체 후보 진단보다 과제가 작으며 시간·오류 수를 동등한 성능 비교로 쓰지 않는다.

운영 코드·검사·ML·보고서·승인 상태는 변경하지 않는다. 새 의존성·유료 호출·웹 조사·재학습은 없다. `compare_candidate_flow`는 기존 동결 근거를 읽고 OllamaProvider에 한 번만 요청하며 Router·보고서 저장 경로를 호출하지 않는다. 기본 실행은 준비만 하고 `--run`이 있을 때만 GPU를 호출한다. 실패·Schema 오류도 자동 교정하지 않는다.

## 작성 예시 준비

[원주 작성 예시 초안](examples/wonju_candidate_flow_draft.json)을 만들었다. 공식 사실은 2026-06 관광소비 60,562,672,000원과 강진 환급의 운영 원리로 제한하고, 원주 적용은 조건부 제안으로 분리했다. 참여 업체 협의→결제 증빙→자격·취소·중복 확인→확정 규칙으로 지급→상품권 사용 집계를 각 역할의 행동·산출물로 표현했다. 절대 소비액만으로 소비 부족이나 환급 필요성을 단정하지 않으며 예산·지급률·사업 효과를 만들지 않는다.

현재 `ai_draft_pending_human_review`이며, 사람 검토를 마친 예시가 아니다. 사용자에게 내용 검토를 요청했다. `--reviewed-example`은 `human_reviewed_writing_example` 상태만 허용한다. 확인 답변 전에는 해당 상태를 바꾸거나 예시 포함 실험을 실행하지 않는다. 이 검토는 작성 예시 사용에 한정되며 실제 사업·법적 적합성·효과의 승인이 아니다.

## 예시 없는 짧은 요청의 실제 결과

- 증빙: `storage/candidate_flow_d18aba536dc44ad99461d95703d1b209.json`에 입력 전문·답변·시간·토큰을 보존했다.
- 부모 입력 SHA: `9271601f46105352ab0d06e64866ba4c0d2888568cc248aeeeb188b366846b92`.
- 새 요청 SHA: `84371b9c56e0fc0fd5235d419508d6b8e1aeec0e9cfc0382bc461116d80644d9`.
- Qwen3:14b, think=False, temperature 0.15, 출력 상한 5,600, 문맥 40,960, timeout 420초. 최종 한 번 31.413초, 입력 15,468 / 출력 435토큰. 완전 JSON·Schema 성공, 보고서 승인 false.
- 실제 제목은 **야간관광 특화도시 예산 편성**이었다. observed_fact에는 원주 수치 대신 전주 사례의 목적 `야간 콘텐츠와 관광여건을 지속 운영할 예산 구조 마련`을 복사했다.
- 실행 단계는 `관광산업과: 예산 편성 → 사업 참여자: 사업 운영 → 관광객: 체류 및 소비`뿐이다. 신청·이용 절차·지출 증빙·담당자의 확인 행동이 없고 마지막 산출물은 `야간 체류 및 지역 내 소비 증가`로서 검증되지 않은 효과다.
- not_supported에는 성과를 보장하지 않는다는 한계를 적고 needs_evidence를 반환했다. 그러나 이 표시가 불충분한 사업 설계를 보완하지는 않는다.
- `registered_fact_ids=true`는 ID가 등록 목록에 있다는 뜻일 뿐이다. 이번처럼 타지역 사례 ID도 목록에는 존재한다. 원주 사실과 주장이 일치한다는 검증으로 해석하지 않는다. case_read 역시 원문 조회 여부만 의미한다.
- 결론: 이번 한 입력에서 요청 단축만으로 구체적 이용 흐름을 얻지 못했다. 예산·측정 필드를 빼고 응답이 짧아진 것을 품질 개선으로 보고하지 않는다. 기존 검사나 프롬프트를 운영에 반영하지 않았다.

처음 제한 환경의 연결 실패는 `storage/candidate_flow_ba8de9d72981462087dc86d9dda283c9.json`에 보존했다. 사용자 승인된 네트워크 경로에서 위 한 번의 실제 응답을 받았다. 준비만 한 요청은 `storage/candidate_flow_4e37e10463ff477c9be6365c7550b471.json`이다.

## 재현과 검증

```powershell
backend/.venv/Scripts/python.exe -m ai_server.app.scripts.compare_candidate_flow storage/candidate_comparison_input_5207b2af04f74b3d909b4cd2abf7dd14.json --run
backend/.venv/Scripts/python.exe -m unittest ai_server.test_candidate_flow ai_server.test_candidate_replay ai_server.test_candidate_thinking_comparison -q
```

진단 테스트는 근거/상한 보존·원본 비변경·입력 hash 변조 거절·미검토 예시 차단·예시 메시지만 추가되는 비교를 확인한다. 예시 포함 실험은 사용자 검토 응답 대기 중이며, 아직 비교 결과가 없다. 검토 뒤에도 같은 지역·같은 과제의 예시 복사 가능성이 있으므로 다지역 일반화나 독립 평가 통과로 주장하지 않는다.

진단 관련 unittest 8개, Python 컴파일, 변경 문서 diff 공백 검사 통과. pytest는 기존 가상환경에 미설치되어 실행하지 않았다. 프런트엔드·운영 API·ML 변경이 없어 build·재학습은 실행하지 않았다.

## 사용자 예시 사용 승인 후 비교 완료

사용자가 예시 사용 질문에 `응 계속 진행할거 진행해줘`로 답하여 예시 상태를 `human_reviewed_writing_example`로 변경했다. 이는 작성 예시 사용 동의이며 전문가 사업 검증이 아니다. 위의 검토 대기 기록은 승인 전 상태다.

- 명령: 위 실행 명령에 `--reviewed-example docs/examples/wonju_candidate_flow_draft.json` 추가.
- 실제 결과: `storage/candidate_flow_fada69ae0191485295b356186455788c.json`.
- 입력 SHA: `d08bf2ecccd76cb300946177dfeb831e8f6c10350cb782f06466fe1d51d44387`.
- 원래 요청과 비교하여 예시 메시지 한 개를 제거하면 메시지·Schema·모델·출력 상한이 모두 동일함을 Python으로 확인했다. think=False 유지, 재시도 없이 1회 실행.

| 각 1회 | 예시 없음 | 검토 예시 포함 |
|---|---:|---:|
| 시간 | 31.413초 | 53.163초 |
| 입력/출력 토큰 | 15,468 / 435 | 16,411 / 727 |
| Schema | 통과 | 통과 |
| 보고서 승인 | false | false |

예시 포함 제목은 `야간 체류 유도를 위한 원주 야간관광 특화 콘텐츠 운영`이다. 예산 편성 자체를 제목으로 삼지 않았고 원주 2026-06 숙박 비율 12.5%, 평균 숙박일 2.76일에 dataset 4/5를 올바르게 연결했다. 기획 담당자·업체·방문객·분석 담당자로 4단계를 구분하고 확정 운영 방식/효과의 미확인 상태를 밝혔다. 환급 예시를 그대로 사업으로 복사하지는 않았다.

그러나 실제 내용에는 다음 문제가 남는다.

1. observed_fact에 `이는 야간 체류 유도가 필요한 시점이다`를 붙였다. 해당 두 관측값만으로 야간관광 필요성을 확정할 수 없으며 관측 사실과 판단을 혼합했다.
2. 참여 업체가 제공할 서비스, 방문객 신청·이용·결제 절차와 운영자가 확인할 증빙이 없다. `특화된 서비스 제공`, `야간 체류를 경험`은 실행 가능한 이용 흐름이 아니다.
3. 전주 예산서의 예산 편성 정보를 `야간 콘텐츠와 체류 여건을 강화하는 운영 원리`의 증거로 확장했다. 성공 수치를 만들지는 않았으나 해당 카드만으로 구체적 운영 원리는 확인되지 않는다.
4. 소비 기록을 누가 어떤 원장에서 수집할지, 비교 설계가 무엇인지 없이 `효과 분석 보고서`를 산출물로 요구했다. 지역 전체 자연 변화와 사업 효과를 구분하는 실행 절차가 없다.

결론은 **관측 출처 연결과 문장 구조의 부분적 변화는 보였지만, 실제 이용 흐름 품질은 미달**이다. 동일 원주 입력의 단회 비교이며 예시 효과의 반복성·다지역 일반화는 미검증이다. 예산·측정 세부를 요구하지 않은 실험이라 그 필드의 오류 감소도 주장하지 않는다. 운영 프롬프트·보고서·ML·승인 상태는 변경하지 않았다. 유료 호출·설치·추가 도구 조회는 없었다. 승인 상태 변경 후 진단 테스트 4개 재통과.

다음 검증은 예시를 계속 늘리기보다, 예산서를 운영 모델로 해석하는 문제를 분리해 살펴보는 것이 적절하다. 실제 운영 절차가 있는 카드만 사용하는 작은 대조를 준비하고, 근거 제한에 따른 후보 다양성 손실도 함께 평가할 필요가 있다. 이번에는 추가 GPU 호출이나 운영 사례 필터 변경까지 실행하지 않았다.
