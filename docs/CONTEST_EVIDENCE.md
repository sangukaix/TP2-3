# 공모전 성과·증빙 관리

## 원칙

아직 측정하지 않은 방문객 증가, 매출 증가, 만족도, 예측 정확도를 결과처럼 쓰지 않는다. 모든 숫자에는 데이터 기간·대상·계산 방법·측정일을 남긴다.

## 확보할 증빙

| 구분 | 실제로 측정할 값 | 증빙 방법 |
|---|---|---|
| 데이터 활용 | 사용 파일, 기간, 지역 수, 전처리 과정 | 데이터 사전·코드·출처 URL |
| ML | Baseline/후보 모델별 MAE·RMSE·MAPE | 고정 Test 결과와 실행 로그 |
| RAG | 질문별 검색 문서의 관련성·출처 표시 | 테스트 질문표와 화면 캡처 |
| AI 전략 | 근거 없는 수치·관광지 생성 여부 | 검토 체크리스트 |
| 사용자 평가 | 유용성·이해도·재사용 의향 | 설문 원본, 익명 요약 |
| 서비스 | 보고서 생성·저장·피드백 기능 | 시연 영상·배포 화면 |

## 보고서 작성 문장 규칙

- 실제값: "2026년 1~6월 데이터에서 관측됨"처럼 기간을 쓴다.
- 예측값: "모델 예측"임을 명시한다.
- 기대효과: 보장된 성과가 아니라 "기대" 또는 "검증 필요"라고 쓴다.
- 사용자 평가는 표본 수와 질문 척도를 함께 쓴다.

## 권장 사용자 테스트

지역 관광·숙박·음식점 관계자 또는 일반 사용자에게 한 지역 보고서를 보여 주고, 5점 척도로 유용성·이해도·실행 가능성을 조사한다. 인터뷰·설문 동의를 받고 개인정보는 최소한으로 수집한다.
