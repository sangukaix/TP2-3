# PPT v8 사례·수치 표시 점검

## 확인 범위

- 승인된 v6 디자인 원본, v7 코드, 저장 원주 보고서 `storage/ppt_audit_20260905/enriched.json`를 사용했다. 원본 보고서·SQL·학습 모델은 수정하지 않았다.
- 저장 보고서 사례는 6개이며 야간관광 관련 자료가 3개였다. PPT는 선정 사례 다음에 입력 순서대로 배치해서 중복 유형을 강조했다.
- 사례 분류가 전체 JSON의 ‘숙박’ 단어를 우선 검사하여 부수 조건까지 사업의 핵심 방식으로 분류하는 문제를 수정했다. 사업명·운영방식을 우선 사용한다.
- 전국 선택 로직 `case_scope.select_case_cards`는 동일 시도에만 제한하지 않는다. 이번 수정은 데이터 전수 학습이나 새로운 웹조사가 아니다.

## 적용

- 선정 ID를 유지하고, 나머지 칸은 서로 다른 운영방식 먼저 선택한다. 원주 저장 샘플은 강진 환급 / 관광주민증 / 야간관광 / 숙박 할인 자료를 표시한다. 실제 확인한 카드가 4개 미만이면 자료 부족을 표시한다.
- 차트와 표는 사업 기간 처음 3개 저장 예측값을 사용한다. PPT 차트의 내장 워크북과 캐시를 동일 정밀도로 저장한다.
- 예측값 대비 목표는 `execution_scenario`의 명시적 입력으로만 만든다. 이번 디자인 샘플은 최종 월 방문 2%, 소비 3% 목표율을 단계 적용했으며 원 보고서의 목표는 변경하지 않았다.
- 저장 예측 모델의 검증 성능이 전년동월 기준선보다 낮은 경우 출처 페이지에 주의를 표시한다. 개선된 목표값을 실제 인과적 사업효과라고 주장하지 않는다.
- 월별 레이블은 겹침 방지를 위해 고정된 네이티브 차트 영역 위의 편집 가능한 텍스트다. 앱 재출력 시 데이터에서 재생성된다. PPT에서 차트 데이터를 직접 바꾸면 해당 텍스트도 함께 수정해야 한다.
- 공개 PPT 함수에 연결했으며 새 출력 버전 키로 이전 캐시와 구분한다. 실행 서버 재시작/리로드와 기존 문서 재다운로드가 필요할 수 있다.

## 범위 제한

이번 점검은 저장 보고서 재출력·템플릿·사례 선택 코드 대상이다. 실시간 LLM 기획 생성, 전체 전국 DB 완전성, 웹 검색 연결, 실제 사업비 단가는 새로 검증하지 않았다.
