# 소속 시도 관측 맥락 연결 (2026-09-16, D-187)

시군구 기획서 생성 범위는 유지한다. 새 시도 자료는 같은 관측월의 관광 흐름을 설명하는 보조 근거이며, 시도 기획서 생성·새 ML 학습·KPI 변경·전국 순위 변경에는 사용하지 않는다.

## 보관과 재현

- 원본: `data/source_snapshots/provincial_tourism_20260916/` — 공유 폴더 ZIP 415개, 3,814,307바이트. `manifest.json`에 상대경로·SHA-256·원래 공유 경로를 보관한다. 복사 후 모든 해시를 대조했다. 운영 시 공유 폴더에 접속하지 않는다.
- 가공: `data/processed/provincial_tourism/monthly_context.csv`, `summary.json`.
- MySQL: `provincial_tourism_monthly_context`. 기존 시군구 fact, 모델, 지역 카탈로그, 저장 보고서는 변경하지 않는다.
- 15개 시도 × 202401~202606 30개월 × 4개 지표 = 1,800행. 지표는 순 방문자 수, 외지인 관광소비(천 원→원), 숙박 방문 비율, 평균 숙박일수다.
- 방문자 연인원, 전국 평균, 내국인 전체 소비를 위 지표와 섞지 않는다. 정확한 CSV 파일명·열·소비 업종 `전체` 행을 선택한다. 빈 값·비정상 수치·상충 중복은 적재 전에 실패한다.
- 옛 이름 `강원도`, `전라북도`와 비어 있는 `전남광주통합특별시` 폴더는 보관만 한다. 실제 강원특별자치도·전북특별자치도 자료를 사용한다. 대전·경북 원본 폴더는 이번 묶음에 없다.
- 시도 코드는 기존 공식 시군구 코드표의 시도명/코드 앞 두 자리를 사용한다. 시군구 행이 없는 세종은 시도 행정코드 36으로 보관하되 생성 지역에 추가하지 않는다.

다른 PC에서도 원본 스냅샷과 기존 지역코드표·`.env`의 MySQL 설정을 준비한 뒤 프로젝트 루트에서 실행한다.

```powershell
.\backend\.venv\Scripts\python.exe -m data_pipeline.tools.build_provincial_context
.\backend\.venv\Scripts\python.exe -m data_pipeline.tools.build_provincial_context --apply
```

첫 명령은 CSV 재현과 원본 검증만, `--apply`는 새 보조 테이블 생성 및 키 기준 upsert까지 수행한다. CSV는 원본 ZIP과 분리한다. ZIP 내부를 직접 풀어 덮어쓰지 않는다.

## 생성 시 전달

```text
로컬 원본 ZIP → 검증·가공 CSV → MySQL 시도 관측 보조 테이블
  + 선택 시군구의 기존 원자료 이력
  → build_region_snapshot.provincial_context
  → Evidence / Case Scout의 조사 맥락
  → get_region_metrics → Qwen 비교 / Gemma 작성·보완
  → evidence_sources에 비교 요약·출처를 보존 → 기존 PPT/Word 공통 출력
```

- MySQL `dim_region`의 시군구 코드/시도명을 확인한 뒤 해당 시도만 연결한다.
- 선택 시군구의 최신 관측월과 같은 시도 관측월을 사용한다. 증감률은 각각 `(이번 월/전년 같은 월 - 1) × 100`이며 차이는 `%p`다. 전년 값이 없거나 0이면 증감률을 만들지 않는다.
- 숙박 비율·숙박일수도 동일 관측월의 값만 비교한다. 최신월이 맞지 않으면 지난달 값을 현재 자료처럼 사용하지 않는다.
- 외지인 기준의 행정 경계가 다르므로 총량을 합치거나 점유율·유사도 순위·인과효과로 해석하지 않는다. 모델이나 사업 효과 예측이 아닌 상위 지역 배경이다.
- MySQL/시도 자료가 없으면 이 비교만 생략한다. 시군구 생성 준비 상태를 낮추거나 자료 부족 문구를 기획서에 강제로 추가하지 않는다.
- 로컬 도구를 추가하지 않고 기존 `get_region_metrics` 응답에 작은 비교 묶음을 붙인다. 유료 호출 횟수·후보 보완 횟수·문맥 상한을 늘리지 않는다.
- 새 생성 결과의 근거 목록에 보존하며 기존 저장 기획안을 소급 수정하지 않는다. 발표 디자인은 그대로 유지한다.

## 검증

- 관련 unittest 55개 통과: 동일월·0분모·다른 지역 배제·SQL 실패 시 생략·원본 재현·도구/본문 보완의 출처 전달 포함.
- 실제 SQL 조회와 시군구 snapshot 확인: 제주시/철원군/부평구 연결, 대전 서구(시도 원본 없음)·강남구(시군구 202607, 시도 202606)는 비교 생략.
- 예: 202606 철원군 순 방문 전년 대비 -12.41%, 강원 전체 -7.04%; 외지인 소비 철원 -2.45%, 강원 +6.50%. 제주시 방문 -8.95%, 제주 전체 -8.02%. 사업 효과나 향후 전망이 아니다.
- 415개 ZIP 해시 및 MySQL 1,800행을 가공 CSV와 대조한다. 기존 지역 모델을 재학습하지 않는다.
- 실제 Ollama `/api/tags` 및 개발 AI 서버 8112/웹 프록시 5176의 LLM 상태에서 Qwen/Gemma ACTIVE 확인. 8001은 배포 기준 포트이며 현재 개발 포트가 아니다. 유선에서도 접속된다.
- 이번 작업에서 LLM 추론·유료 생성·새 PPT/Word 렌더는 실행하지 않았다. 근거 전달 검증과 최종 문장 품질 검증은 구분한다.
