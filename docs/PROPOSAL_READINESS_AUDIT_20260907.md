## 데이터와 ML

```text
공식 다운로드 스냅샷
  → 지역별 월간 표 검증(지역코드 + 연월, 월 누락/음수/비수치 차단)
  → 7개 지표의 시간순 Train → Validation → Test
  → 전년 동월 seasonal-naive 기준선과 비교
  → 검증 메타데이터·Joblib 저장
  → 생성 시점: 저장 모델 + 원자료 fingerprint 일치할 때만 자연추세 사용
```

- 89개 활성 지역은 원자료 구조와 7개 타깃 열을 모두 통과했다. 88개는 `2024-01~2026-06`, 강남구는 `2024-01~2026-07`까지다.
- 실제 MySQL 비교층은 `dim_region` 267개, 월별 사실 5,040행, 계획 컨텍스트 167개, peer 비교 835행, 전국 빅데이터 기간지표 4,332행을 읽을 수 있었다. 이 범위가 곧 89개 지역의 저장 ML 범위와 같지는 않다. **ML은 89개 활성 스냅샷**, 전국 비교는 **MySQL 컨텍스트가 있는 지역**에서 각각 사용한다.
- 모든 89개 카탈로그 행에 **정확한 다운로드 URL 누락** 경고가 있다. 현재 로컬 스냅샷의 재현성은 있으나, 제출용 출처에는 실제 한국관광 데이터랩 다운로드 URL/일시를 보강해야 한다.
- 원주의 방문자·관광소비·평균 숙박일 등 일부 모델은 마지막 시험 구간에서 전년 동월 기준선보다 좋지 않다. 따라서 그래프는 표시하되 사업 효과나 정확도 우수의 증거로 쓰지 않는다.
- ML은 사업 전 자연추세만 제공한다. “사업을 실행하면 몇 명/몇 원 증가”는 별도의 비교집단·운영 집계자료가 없으면 목표 가정 또는 사후 검증 항목으로만 쓴다.

## 타지역 사례와 RAG

```text
선택 지역 문제/관측
  → 같은 시도 사례
  → 타시도 관광지표 peer 사례
  → 전국 사업·다른 운영 원리 사례
  → 공식 원문 읽기
  → 유지/제외/축소/변경 조건 비교
```

- 현재 카드: 강진 지역환급, 디지털 관광주민증, 야간관광 특화도시, 전주 예산, 전국 숙박할인, 야간축제. 서로 다른 운영 원리를 비교하는 출발점이다.
- 강진의 과거 “46%” 문구는 집계 범위·원자료가 불명확해 정량 성과로 인용하지 않는다.
- 이번 점검에서 같은 PDF의 여러 페이지가 하나의 `source_id`로 덮어써질 수 있던 버그를 수정했다. 이제 `(source_id, chunk_id)`를 모두 보존하고, PDF 인용 전에는 반환된 청크를 순서대로 읽어야 한다. PPT 출처 목록도 같은 문서의 선택 페이지를 합쳐 표시한다.
- 데이터 세미나 PDF는 75~99쪽 중 23쪽이 이미지/특수 폰트로 텍스트 추출되지 않았다. 화면으로 확인한 76쪽의 **데이터 정의 요약**과 텍스트 추출된 89쪽만 등록했다. 자동 OCR 결과를 사실 근거로 추가하지 않았다.

## 현재 생성 중 실제 흐름

```text
React 요청
  → AI Server: 지역 snapshot / MySQL 전국 비교 / 저장 ML
  → Evidence Agent: 공식 Open API + 로컬 RAG + (키가 있을 때만) 무료 공식 웹검색
  → Case Agent: 전국 범위 사례 후보와 적용 조건
  → Qwen: 지역 적합성·서로 다른 후보 비교·검수
  → Gemma: 5단계 실행안, 비용 산식, KPI 설계·수정
  → 코드 품질검사: 출처·기간·%/%p·산식·KPI·사례 원문 읽기 확인
  → 구조화 결과 → PPTX/Word
```

로컬 모델은 DB/파일에 직접 접속하지 않는다. 서버가 허용된 읽기 전용 도구로 필요한 사실만 전달한다. 소비 업종 구성도 이제 `get_region_metrics`에 포함되며, 비중만으로 원인이나 사업 효과를 단정하지 않는 규칙이 함께 전달된다.

## 아직 필요한 자료 - 우선순위

1. **선택 지역의 실제 운영 가능 조건**: 관광 인센티브, 지역화폐, 가맹점/정산, 개인정보·중복수혜 규정의 공식 URL/PDF/HWP.
2. **서로 다른 방식의 공식 결과/결산 자료 2~3건**: 참여대상·건수, 예산/집행액, 측정 정의, 취소/민원 등 운영 결과가 있어야 한다.
3. **기획용 견적 근거**: 운영일수, 참여처 수, 인력·정산·홍보·평가 단가, VAT 포함 여부와 기준일. 없으면 문서에는 참고 가정으로만 남긴다.
4. **사후 성과 확인용 익명 집계표 설계**: 신청/적격/지급/취소, 인정 소비액, 재사용, 비교집단, 기준월·원자료 설명. 개인식별·개인 이동 기록은 받지 않는다.
5. **정확한 출처 메타데이터**: 89개 스냅샷 각각의 데이터랩 다운로드 URL·다운로드 일시. 인구 규모 비교가 필요하다면 기준월이 있는 공식 주민등록 인구표도 별도로 필요하다.

## 최종 판단

현재 상태는 **안전장치가 있는 기획 초안 생성 시스템**이다. 지역 현황, ML 자연추세, 전국 비교, 공식 사례, 출처 목록을 연결할 수 있다. 그러나 정량 사업 효과·확정 예산·법적 운영 가능성까지 검증한 “최종 실행계획 시스템”은 아니다.

이번 점검의 선택 회귀 테스트 171개와 실제 원주 문맥 예산 사전검사는 통과했다. 테스트의 의도적 문서 저장 실패 메시지는 오류 경로 검증용이며, 실제 기획서 저장 실패를 뜻하지 않는다.

위 1~3번 자료가 추가되고, 선택 지역의 최신 월 원자료로 시간순 재검증을 한 뒤, 실제 한 지역 기획안을 사람 검토까지 통과시키면 그때 최종본에 가깝다고 판단하는 것이 맞다.
