# 단계별 구현 계획

각 단계는 앞 단계의 완료 기준을 충족한 뒤 진행한다. 실제 파일·결과가 없는 상태에서 뒤 단계를 가정해 구현하지 않는다.

| 단계 | 작업 | 산출물 | 완료 기준 |
|---|---|---|---|
| 0 | 범위 확인 | 문제·사용자·MVP 확정 | 이 문서와 `DECISIONS.md` 검토 완료 |
| 1 | 데이터 타당성 확인 | 데이터 목록·데이터 사전 | 파일, 기간, 지역키, 단위, 이용조건 확인 |
| 2 | 원본 보관·EDA | 탐색 노트북/스크립트, 품질표 | 결측·중복·분포·기간 단절 확인 |
| 3 | 전처리·통합 | 재현 가능한 처리 코드, processed 데이터 | `region_code + year_month` 결합 검증 |
| 4 | Feature·기준모델 | Feature 정의서, baseline 결과 | 예측 시점 누수 없음 확인 |
| 5 | ML 후보 비교 | 평가표, Joblib, 메타데이터 | 시간 기준 Test에서 기준모델 비교 |
| 6 | MySQL·일반 API | 테이블, Pydantic 스키마, API 테스트 | 실제 지표 조회 가능 |
| 7 | AI 예측 API | `/ai/predict`, 모델 로딩 테스트 | 저장 모델 예측 재현 |
| 8 | RAG 구축 | 지역 문서·공식 성공사례 레지스트리, ChromaDB, 검색 테스트 | 공식 출처·지역필터·사례 URL 표시 |
| 9 | 전략 생성 | 고정 5-Agent 흐름, `/ai/generate-report`, JSON Schema | 수치·예측·공식 사례·지역 적합성 기반 응답 |
| 10 | React/Vite 화면 | 대시보드·예측·보고서 UI | API 연동, lint/build 성공 |
| 11 | 저장·피드백 | 보고서·피드백 API/UI | 명시적 저장과 검증 완료 |
| 12 | 통합 테스트 | E2E 테스트·오류 시나리오 | 대표 흐름과 자료 부족 흐름 확인 |
| 13 | 사용자 평가 | 설문·인터뷰 결과 | 실제 표본·방법을 기록 |
| 14 | AWS 배포 | Nginx 설정, 운영 문서 | 외부 URL에서 정상 동작 |
| 15 | 공모전 제출물 | 보고서·발표·시연 영상 | 실제 측정값과 증빙 반영 |

## 권장 개발 순서

```text
데이터 확인
 → EDA·전처리
 → ML 기준모델·후보 비교
 → MySQL + Backend API
 → AI 예측 API
 → RAG 문서·ChromaDB
 → OpenAI 전략 생성
 → React/Vite 화면
 → 통합 테스트·사용자 평가
 → EC2 + Nginx 배포
 → 공모전 자료 제작
```

## 매 단계의 공통 기록

- 사용한 입력 파일과 기간
- 실행 명령과 실행일
- 결과 요약 및 화면·로그 증빙
- 실패·제약 사항
- 다음 단계로 넘어가기 위한 결정

## 시작 시 할 일

1. `data/raw/`에 실제로 받은 파일을 넣는다.
2. 파일을 수정하지 않고 목록·컬럼·기간·행 수·지역코드·기준연월을 점검한다.
3. "다음 달 방문객" 타깃을 만들 수 있는지와 최소 필요 이력을 판단한다.
4. 부족하면 다른 예측 목표 또는 분석 중심 MVP를 근거와 함께 제안하고 승인받는다.
