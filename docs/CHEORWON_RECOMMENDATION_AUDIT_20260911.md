# 철원군 기획서 반복 추천 원인 점검

검토일: 2026-09-11. 첨부 Word/PPT 내용, MySQL 저장 보고서 조회 응답, 현재 생성·사례 연결·문서 출력 코드를 대조했다. 원본 파일과 저장 보고서는 변경하지 않았다.

## 결론

전체 기획서의 복사·붙여넣기는 확인되지 않았다. 다만 공통 사례 의존, 자동 추천 유형 제한, 인용 재연결의 ID 정렬, 후보 선정 이유 덮어쓰기 때문에 같은 사업과 사례가 반복되기 쉬운 구조였다. 이번 철원 결과만으로 반값여행이 가장 적합하다고 입증할 수 없다. 다른 사업으로 임의 교체하거나 인구 보정값을 만들지 않았다.

## 수치와 기간

- ML 표는 2026년 10~12월, 월별 방문 기준 전망 합계 1,370,831명이다. 목표 합계 1,537,696명, 추가 166,865명이다.
- 최종월 +20%는 강진 발표 +25% × 계획 채택 비율 80%의 기존 기본 규칙이다. 주민 인구·철원 사업 효과를 학습해서 구한 비율이 아니다. 기존 사용자 승인 목표 규칙은 이번 수정에서 바꾸지 않았다.
- 방문과 소비는 같은 월 소비/방문 비율을 사용하므로 월별 증가율이 같다. 합계 증가율은 월별 비중 차이로 방문 12.17%, 소비 11.70%이다.
- 견적: ceil(추가 방문 목표 × 1%)=1,669건; 지원 1,669×50,000=83,450,000원. 인력 max(20×3,ceil(1,669/25))=67인일×150,000=10,050,000원. 시스템·홍보·집계 16,000,000원, 직접비 109,500,000원, 예비비 10%=10,950,000원, 총 120,450,000원. 계산은 맞지만 1%, 건당 지원액과 단가는 기획 가정이다. 이 견적이 지역 전체 방문 +20%를 달성한다는 검증은 없다.
- 표지와 ML 표는 10~12월인데 본문 timeframe 및 준비 단계는 9~12월(4개월)이었다. 공통 사업기간 정규화로 새 생성·문서 준비에서는 10~12월로 일치시키고 원래 일정은 planning_decision.period_alignment에 보관한다.

## 시스템 수정

1. 유효한 사례 인용 순서를 유지하고 기존 선정 이유를 보존한다. 잘못된/없는 인용만 같은 운영 방식의 공식 문서로 보완한다. 보완은 지역 검색 맥락→문서 등급→ID 순서이며 적합성 모델로 표시하지 않는다.
2. 자동 추천에서 예약·교통·체험도 공식 근거가 있으면 허용한다. 사용자가 특정 사업 방향을 고른 경우의 제한은 유지한다. 예산서가 운영 사례 비교 슬롯을 차지하지 않게 한다.
3. 별도 local_prompts를 쓰는 Qwen/Gemma 도구 경로에 후보별 지역 지표와 바꿀 행동, 대안과의 차이, 사업기간 지침을 직접 반영한다. 동일 local_fit은 기존 보완 요청에 포함하며 새로운 LLM 호출 횟수는 추가하지 않는다.
4. PPT/Word 사례는 핵심 운영 참고, 후보 비교에 사용한 사례, 추가 운영 참고로 역할을 구분한다. 추가 카드가 실제 비교 후보인 것처럼 보이지 않게 한다.
5. 새 사업기간과 세부 일정이 일치하도록 서버에서 정규화한다. ML 값·목표율·견적·선택 사업·승인 상태는 바꾸지 않는다.

## 검증과 남은 확인

실제 철원 저장본의 오프라인 재생에서 기간 10~12월 일치, ML/검수/목표/견적/선택 후보 유지, 견적 합계를 확인했다. 저장 보고서를 덮어쓰거나 유료 API를 호출하지 않았다.

로컬 Ollama 상태 조회는 처음 샌드박스 소켓 제한으로 실패했고 허용된 재시도에서도 연결 시간이 초과됐다. 따라서 수정 후 실제 Qwen·Gemma 응답 품질과 다른 사업 선택 여부는 아직 실측하지 못했다. 연결 복구 후 같은 철원 입력과 원주 별도 입력으로 후보별 판단과 최종 본문을 다시 비교해야 한다. 이번 코드 수정만으로 추천 품질 개선이 입증된 것은 아니다.

첨부 Word와 14장 PPT의 XML 본문·표를 확인했다. PowerPoint COM 렌더는 Windows 로그온 세션 오류(0x80070520)로 실패했으므로 이번 검토에서 새 시각 렌더 품질을 승인하지 않았다.
