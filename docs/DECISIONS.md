### D-137 지역 자료 준비 색상과 로컬 연결 점검 분리 (2026-09-10)

- 사용자 요청: 생성에 필요한 자료가 준비된 지역을 초록색으로 구분한다.
- 기존 `verified`(저장 기획안 품질·출력 승인)와 별도로 `generation_ready = data_ready AND 현재 Qwen/Gemma 설치·연결 확인`을 제공한다. 24시간 이내 자료 감사만 사용하며 만료/조회 실패는 초록색이 아니다. 모델 추론 성공이나 향후 오류 없음의 보장은 아니다.
- 대시보드와 공통 지역 선택기에 초록색·준비됨을 함께 표시한다. 미준비/미점검은 확인 필요로 표시하지만 대시보드 조회는 유지한다. 로컬 상태는 60초마다 재확인하며 생성 시작에서도 별도로 확인한다.
- Ollama 목록 조회 제한은 5→15초, 생성 선행 연결 실패는 무료 목록 조회만 1회 재시도한다. 지역 자료 오류와 모델 연결/설치 오류를 구분해 안내한다. 유료 생성 상한·추론 재시도는 늘리지 않는다.
- 실측: 등록 89지역의 기존 데이터 감사 조건 통과, 관악구 포함. 저장 기획안 최종 품질/출력까지 verified인 지역은 0개이며 이를 승인으로 바꾸지 않았다. 두 로컬 모델 상태 active 확인. 실제 새 LLM 기획안 생성은 실행하지 않았다.

### D-136 기획 조건 입력을 지원 범위로 제한 (2026-09-10)

- 사용자 승인: 자유 입력으로 기획안이 흔들리지 않도록 감당 가능한 항목만 남긴다.
- React 생성 화면은 `guided_v1`: 지역, 사업 방향(추천/소비·환급/숙박·체류/야간/재방문), 참고 예산 총액, 시작 월부터 3개월, 자원 300자, 제외 선택, 메모 500자만 받는다. KPI 직접 입력·최소/최대 예산 범위·확정 상한·종료일·첨부·장문 필수 조건은 제거한다.
- 서버가 enum·문자 수·충돌·3개월 날짜를 검증한다. 시작 월 미입력은 서버 현재 월로 정한다. ML 전망이 전체 기간을 포함하지 못하면 외부 사례 조사 전에 안내한다.
- 공식 사례와 설계 후보를 사업 방식 함수로 제한하며, 제외 조건은 혼합 방식에도 적용한다. 허용된 방식이 하나뿐이면 비교를 위해 다른 사업을 억지로 요구하지 않는다. 선택 후보가 조건 밖이면 다른 후보의 제목과 기존 요약을 섞지 않고 조정 안내를 반환한다. 다운로드 사례 카드에도 같은 필터를 적용한다.
- 입력 예산은 참고 견적 총액을 항목 비중으로 재배분한다. ML 수치와 목표 달성 가능성을 역산하지 않으며, 인력·운영량·실제 집행 가능성은 보장하지 않는다. 기존 저장 보고서와 legacy API 계약은 유지한다. 구형 브라우저 초안을 새 폼에서 읽을 때 숨겨진 필드는 전송하지 않는다.
- 검증은 입력/선정/견적 코드와 기존 회귀 테스트로 수행한다. 실제 LLM 생성 품질 승인과 구분한다. 유료 호출·새 라이브러리·모델 재학습 없음.

### D-126 방문 증가분으로 설명하는 소비 목표 산식 (2026-09-09)

- 사용자 요청에 따라 방문·소비 목표율이 같은 기본 기획안은 `월별 ML 소비액 ÷ ML 방문 수`를 기획용 비율로 구하고, `ML 소비액 + 추가 방문 수 × 해당 월 비율`로 PPT 소비 목표를 계산한다. 실제 개인별 평균 소비액이나 검증된 사업 효과로 표시하지 않는다.
- 동일 월 비율을 적용하면 월별 방문·소비 증가율은 수학적으로 같다. 3개월 합계는 월별 가중치가 달라 다를 수 있다. 원주 고정 입력은 방문 3.39%, 소비 3.49%이며 기존 목표식과 동치다. 비율·산식·합계 증가율 설명을 KPI 슬라이드 회색 하단에 표시한다.
- 명시적으로 서로 다르게 지정한 방문·소비 목표율은 그대로 각각 적용한다. 방문이 0인 월의 소비/방문 비율은 만들지 않고 기존 명시 목표식으로 계산한다. 저장 보고서·ML·승인은 변경하지 않는다. 웹·Word 기존 목표값과 수학적으로 일치한다.
- PPT 캐시 버전은 `pptx-visitor-spending-formula-v12`. 실제 PowerPoint에서 KPI 슬라이드와 그래프를 출력하여 레이아웃을 확인한다.

- 예산 기준: 현재 원본에는 사업 단가와 견적이 없으므로 금액을 만들지 않는다. 비용 항목, 수량 기준, 공식 단가·비교견적 확보처, 계산식을 제시하고 견적 확보 후 확정한다. 실제 원화 범위는 근거 문서를 RAG에 연결한 뒤에만 계산한다.

### D-020 근거 수집·기획 작성·품질 검토 Multi-Agent

- 상태: D-030으로 확장됨
- 결정: AI 전략 보고서는 Evidence Agent, Planner Agent, Reviewer Agent의 고정 순서로 생성한다. Reviewer가 82점 미만 또는 critical 오류를 판단하면 Planner가 한 번 수정하고 최종 검토한다.

- 주의: Agent 수가 사실성을 보장하지 않는다. 출처가 없는 주장은 버리고, RAG 문서가 없으면 자료 공백을 표시한다. 재작성은 비용·지연을 통제하기 위해 최대 1회로 제한한다.

### D-023 계획 기간별 실행 목표 추이

- 상태: 승인됨
- 결정: 실행 목표 비교는 3개월 또는 6개월의 월별 방문자 수·관광소비액 추이를 표시하며, `미실행`과 `실행 목표` 선을 개별 또는 겹쳐서 검토할 수 있게 한다. 문제 확인, 솔루션, 집행 방법은 각각 독립된 화면 영역으로 표시한다.

### D-033 실제 데이터 안전 표시와 로딩 성능 개선

- 주의: 이 개선은 MySQL 적재나 ML 예측 완료를 뜻하지 않는다. 현재 구현·부분 구현·미구현 범위와 측정값은 `docs/PROJECT_AUDIT.md`에서 관리한다.

### D-035 지역 선택의 Open API 상세보기 분리

- 상태: 승인됨
- 결정: 지역 선택 화면의 `AI 전략기획서 생성` 버튼은 제거하고, 해당 위치에 `지역 정보 상세보기` 버튼을 둔다. 버튼은 팝업에서 관광데이터랩 원자료 요약과 한국관광공사 국문 관광정보 Open API의 관광자원·분류·주소·제공 이미지를 출처별로 나누어 표시한다.
- 이유: 지역 선택은 현황 확인에 집중하고, 유료·시간이 걸릴 수 있는 AI 기획안 생성은 전용 `AI 전략기획` 업무 페이지에서만 수행하게 하기 위해서다.
- 주의: Open API 관광자원 목록은 방문자·관광소비 수치가 아니며, API 실패·빈 결과를 임의 정보로 대체하지 않는다. 인증키는 AI Server `.env`에서만 읽고 React에는 노출하지 않는다.

### D-036 페이지 이동에도 유지되는 AI 전략기획 작업

- 상태: 승인됨
- 결정: AI 전략기획 생성은 동기 HTTP 응답 대기가 아니라 AI Server의 백그라운드 작업으로 등록한다. 브라우저는 지역별 작업 ID를 localStorage에 저장하고 3초 간격으로 상태를 조회한다.
- 이유: Agent 조사·작성·검수는 수십 초 이상 걸릴 수 있으므로, 사용자가 다른 업무 페이지나 탭으로 이동해도 서버 작업과 진행 상태를 유지하기 위해서다.
- 주의: 현재 개발 단계는 AI Server 프로세스 메모리 작업 저장소다. 서버 재시작·배포 중단까지 복구하는 영속 작업 큐는 MySQL/Redis 운영 단계에서 별도로 구현한다. 완료된 결과는 브라우저의 저장 기획서 목록에도 보관한다.

### D-037 AI 주도 전략 설계를 위한 사업 여건 입력 (2026-08-28)

- 상태: 사용자 승인 및 구현.
- 결정: 지역선택 다음에 `/planning` 전략기획 페이지를 둔다. 예산·시기·자원·필수 제약을 중심으로 묻고 현장 정보·선호·문서는 선택으로 둔다. 사용자가 해결책·타깃·사업 내용을 미리 작성해야 하는 서비스로 만들지 않는다.
- AI 역할: 공식 수치와 사례에서 문제·기회를 발견하고 대안을 검토해 목표·방법·실행안을 제안한다. 확정 조건과 선호를 분리하며, 현실적으로 불가능한 조건은 대안/확인 사항으로 설명한다.

### D-072 로컬 LLM의 제한형 무료 공식 웹 검색 도구 (2026-09-03)

- 배경: Qwen·Gemma가 OpenAI Web Search처럼 최신 공식 자료를 전혀 찾지 못하면, 저장된 사례가 부족한 지역에서 기획 후보 비교가 약해진다. 반대로 모델에 브라우저·파일·SQL·임의 HTTP 권한을 직접 주면 프롬프트 인젝션, 비공식 출처 혼입, 비용·할당량 통제가 불가능해진다.
- 결정: `student_budget`에서만 Qwen의 `local_web_query_planner`가 최대 3개 검색 질문을 구조화 JSON으로 설계하고, `OfficialWebSearchClient`가 보고서당 최대 2개 질문을 Tavily로 실행한다. Brave는 팀이 별도 키·계정 조건을 확인해 `LOCAL_WEB_SEARCH_PROVIDERS=tavily,brave`로 지정한 경우에만 앞선 결과가 부족할 때 보조 호출한다. Naver 검색 API는 결과 독립 노출 약관 때문에 LLM 내부 입력 경로에서 제외한다. 서버는 HTTPS 및 `TOURISM_ALLOWED_RESEARCH_DOMAINS`를 다시 검증하고, 제목·URL·짧은 API 요약만 반환한다.
- 안전·품질: 로컬 모델에는 인터넷·브라우저·파일·쉘·DB 직접 권한을 주지 않는다. 검색 후보는 `official_web_search_candidate`와 `source_verification=search_snippet_only`로 표시하며, Planner의 확정 인용·사례카드·자동 RAG 저장에서 제외한다. 원문을 사람이 검수한 뒤에만 기존 JSONL/PDF RAG 등록 절차로 승격한다. 키·응답 원문은 관리자 상태·trace에 남기지 않는다.
- 비용: 실제 키가 있는 공급자만 호출하며, 키가 없거나 무료 할당량·네트워크 오류가 발생해도 OpenAI로 자동 대체하지 않는다. `student_budget`의 OpenAI 최종 검수 1회 제한은 유지한다. Brave의 무료 조건은 계정별 정책으로 확인해야 하며 유료 업그레이드는 자동으로 하지 않는다.
