# 기획안 품질·비용 개선 이력

## 한눈에 보는 변화

```text
원자료 화면
  → 구조화 JSON 1회 생성
  → 공식 근거 RAG/웹 조사 분리
  → 5-Agent 고정 파이프라인
  → ML 자연추세와 사용자 조건 연결
  → 결정적 품질 게이트 + Reviewer 82점 규칙
  → 조사 병렬화·캐시·작업/문서 영속화
```

## 단계별 개선

| 단계 | 이전 문제 | 변경 | 품질 효과 | 비용·속도 효과 |
|---|---|---|---|---|
| 1. 원자료 분리 | 화면 숫자와 AI 문장이 섞일 위험 | MySQL/원자료=사실, ML=예측, RAG=문서, LLM=설명으로 역할 분리 | 수치 환각 방지 | 불필요한 원본 토큰 제거 |
| 2. 구조화 출력 | 긴 자유문장·필드 누락 | Pydantic + OpenAI JSON Schema | 화면·Word가 같은 필드를 안정적으로 사용 | 재파싱·재호출 감소 |
| 3. 공식 근거 | 일반론 중심 제안 | Evidence Agent가 데이터랩·Open API·공식 웹·RAG 수집 | 출처 ID와 기간을 기획에 연결 | 관련 Chunk만 전달 |
| 4. 사례 조사 | 동선 묶기 같은 반복 아이디어 | Case Scout가 운영 방식·예산·관측 성과 조사 | 검증된 타 지역 실행안 비교 | 검수 사례 재사용 |
| 5. 지역 적합성 | 성공사례를 그대로 복사 | Transferability Agent가 적용/제외 조건과 시범 규모 판단 | 지역 여건에 맞지 않는 복제 방지 | Planner의 탐색 범위 축소 |
| 6. 실행 기획 | 뜬구름 문장 | Planner가 문제/제안·해결·정확히 5단계·예산 산식·KPI 작성 | 실제 집행 가능한 형식 | 한 번의 구조화 호출로 작성 |
| 7. 이중 검수 | Reviewer 판단만 신뢰 | Python 게이트가 source_id·5단계·운영·예산·KPI 확인 | 코드로 확인 가능한 누락 차단 | 실패 항목만 한 번 재작성 |
| 8. 점수 강제 | 프롬프트의 82점 규칙을 모델이 어길 수 있음 | 82점 미만 또는 critical 이슈를 Python이 승인 차단 | 최종 승인 일관성 | 낮은 결과의 반복 사용 방지 |
| 9. ML 연결 | 임의 +5%/+8%, 평평한 미실행선 | 저장 ML 자연추세와 사용자 목표를 분리 | 정책효과처럼 보이는 가짜 수치 제거 | 이미 저장한 Joblib 재사용 |
| 10. 동적 기간 | 항상 3개월만 예측 | 미정 3·6개월 비교, 입력 일정은 최대 12개월 | 사업기간과 전망기간 일치 | 필요한 horizon만 계산 |
| 11. 병렬·캐시 | 조사 Agent가 순차·반복 실행 | Evidence/Case 병렬, 근거 1시간·사례 6시간 캐시 | 검수 단계는 매번 유지 | 웹·RAG·입력 토큰 절감 |
| 12. 영속화 | 페이지 이동은 가능하지만 서버 재시작 시 작업 소실 | MySQL 작업 상태·완료 보고서·Word/PPT 저장 | 결과 재조회·다운로드 | 같은 기획안 재생성 비용 감소 |

## 현재 5-Agent와 OpenAI 호출

```text
[로컬 ML: OpenAI 호출 없음]
       ↓
[Evidence] ─┐
            ├─ 병렬 조사
[Case Scout]┘
       ↓
[Transferability]
       ↓
[Planner]
       ↓
[Python 품질 게이트]
       ↓
[Reviewer]
       └─ 미달일 때만 Planner 1회 보완 → Reviewer 1회 재검수
```

정상 1차 통과는 Agent OpenAI 호출 5회다. 재작성 시 최대 7회다. OpenAI 출력 상한은 최대
청구량이 아니라 응답별 안전 상한이며 실제 사용량은 응답 길이에 따라 달라진다. 비용 비교는
OpenAI Usage의 실제 input/output/cached tokens와 작업 ID를 기준으로 기록해야 한다.

## 면접·발표에서 설명할 핵심

- “모델을 크게 바꿨다”보다, 숫자·문서·추천의 책임을 분리해 환각 가능성을 줄였다.
- 공식 사례를 많이 넣는 것만으로 끝내지 않고, 적용 조건과 위험을 별도 Agent가 검토한다.
- LLM 평가만 믿지 않고 코드로 확인 가능한 항목과 82점 기준을 결정적으로 강제한다.
- 전국 원본을 프롬프트에 넣지 않고 선택 지역 요약·ML 전망·Top-K 사례만 전달해 비용을 줄인다.
- 조사만 캐시하고 Planner·Reviewer는 매번 실행해 비용 절감이 품질 검수를 생략하지 않게 했다.
- 완료 보고서와 문서를 저장해 같은 결과를 다시 생성하지 않도록 했다.

아직 실제 사용자 만족도나 정책 성과가 개선되었다고 주장하지 않는다. 이후에는 동일 지역·동일 조건의
기획안을 버전별로 평가해 근거 정확성, 실행 가능성, 담당자 유용성, 호출비, 생성시간을 함께 비교한다.
