# 기획안·챗봇 통합 점검 (2026-09-07)

## 완료와 미완료를 구분

이 문서는 모든 지역의 기획 품질을 보장하는 인증서가 아니다. 등록 89개 지역의 데이터 준비 검사와 실제 기획안 승인·출력 검사는 다르다. 기존 전수 점검에서 데이터 준비는 89개, 최종 검증은 0개였다. 초록색 기준을 낮추거나 목표 증가율을 임의 생성하지 않는다.

지역 검사에서 7개 지표의 이름을 확인하도록 강화했고, 수정 후 재검수 필요 보고서와 오프라인 예시는 초록색으로 인정하지 않는다. 지역별 저장 결과는 `storage/region_readiness_audit.json`에 있다. 오래된 결과는 24시간 후 미검증으로 표시한다.

## 실제 연결 시험

- 실행 모드: student_budget. 유료 자동 대체 없음. 최종 독립 검수 외 OpenAI 자동 조사 차단.
- Qwen3:14b와 Gemma4:26b: 모델 목록뿐 아니라 짧은 실제 추론 완료 확인.
- 원주시 실제 데이터 설명: HTTP 200, Qwen, 입력 14,942 / 출력 97 토큰, 웹 검색·유료 대체 없음. 최초 설명에는 지표 의미를 지나치게 부정한 표현이 있어 지표의 표본·집계 정의를 설명하도록 지시를 보강했다. 이는 모든 답변의 의미 정확성이 검증됐다는 뜻이 아니다.
- 원주 저장 기획안 수정: 최초에는 문맥 한도 초과를 재현. 입력 수정 후 HTTP 200, Gemma, 입력 25,309 / 출력 1,019 토큰, 구조화 본문·5단계 수정안 반환 확인. 시험 수정안은 저장하지 않았다.
- OpenAI 모델 연결 상태는 active였으나, 이번 점검에서 유료 기획 생성이나 최종 검수 호출은 하지 않았다.
- 무료 웹 검색 설정은 enabled지만 configured_providers가 비어 있어 새 검색은 불가하다. 검색을 한 것처럼 표시하지 않는다.

## 수정한 문제

1. 웹 검색 체크박스 때문에 단순 수정까지 검색 단계로 보내던 오류: 검색 의도가 있는 질문에만 검색 요청. 기본 체크 해제.
2. 두 번째 대화부터 AI `answer`가 서버의 `content` 계약과 맞지 않던 오류: 최근 8개를 role/content로 정규화. 대화 기억은 최대 3,000자/메시지이며 원자료가 아니다.
3. 항상 Active로 보이던 표시: 대기·응답·실패를 구분. 응답에 실제 provider/model/usage/web_search_used/fallback을 표시 가능한 형태로 반환.
4. 빈 필드가 기존 문장을 지우거나 임의 필드가 합쳐지는 문제: 허용 본문 필드만 적용. ML·목표·예산은 패치가 덮어쓰지 못함.
5. 수정안 중복 적용: 반영 후 버튼 비활성화. 수정 후 승인 상태를 해제하고 저장 필요 안내.
6. PPT 사업 설명이 수정 전 후보 문구를 우선하던 문제: 최종 본문 solution 우선. 캐시 렌더 버전 r2로 갱신.

## 긴 수정 요청의 범위

기존 본문·실행 단계 수정에는 저장 당시 기획안의 근거를 사용한다. 최신 snapshot 전체와 혼합하지 않는다.
실행 로그만 제외하고 반복 원문은 사전 참조·열/행 표로 표현한다. 복원 시 입력 원문과 같음을 테스트한다.
기존 본문·선정안·관측 해석에 인용되지 않은 RAG 원문은 수정 입력에서 제외하되 전체 원본 보고서에는 보존하고, 해당 출처 목록은 `reference_only_not_read`로 전달한다. 이 목록은 읽은 근거로 인용하지 못한다. 인용된 RAG와 나머지 근거·ML 값은 유지한다.
따라서 새 사업 선정·새 사례 검증까지 자동으로 수행하는 만능 챗봇은 아니다. 그런 변경은 전체 생성·검수가 필요하다. 더 큰 보고서는 여전히 안전 문맥 상한에서 실패할 수 있다.

## 입력 양식은 유지하되 정확히 사용

- 예산: 사업 규모 제약으로 사용. 공식 단가·매출 예측 근거로 사용하지 않음.
- 일정: 준비·운영 기간과 전망 기간 선택에 반영. 확정/조정 가능/미정을 구분.
- 자원: 확보/협의 중을 구분하면 실행안이 구체화됨. 미정은 자원 없음이 아님.
- 현장정보·선호: 공식 관측 사실보다 우선하지 않는 사용자 정보. 과장된 주장이나 모순 입력은 품질을 해칠 수 있어 확인 필요.
- 첨부: 이번 생성의 참고 원문. 공용 RAG나 ML 학습에 자동 등록되지 않으며 저장 보고서의 planning_brief에서는 본문을 제거하므로 후속 챗봇이 원문을 다시 읽는 것은 아니다.
