# 팀 공유폴더 자료 활용 구분

모든 파일은 source inventory에 등록하지만, 검증 전 원본을 곧바로 LLM에 넣지는 않는다. 숫자는 표준화 후 MySQL·ML에, 문서 근거는 별도 RAG에 사용한다.

| 공유폴더 구역 | 활용 목적 | 저장 위치 | 주요 검증 |
| --- | --- | --- | --- |
| 전국데이타_20260831 | 방문·소비·체류 월별 사실, ML feature | MySQL fact, processed ML data | 지역코드, 월, 단위, 상위 시·하위 구 중복 |
| 전국 현황 | 전국 기준선과 거시 추세 | MySQL benchmark | 기준 연도·월, 지역 단위 |
| 지역별 관광현황 CSV | 선택 지역과 전국·시도 비교 | MySQL benchmark | 지역명·지역코드, 전국 현황 중복 |
| 지역별 관광현황 중첩 ZIP | 서울·강원 지역별 월간 관측값 | materialized raw → MySQL fact, ML data | 바깥/내부 hash lineage, CP949 경로, 지역코드, snapshot 중복 |
| 외래객 지역별 방한현황 | 국가별 외래객과 외국인 소비 진단 | MySQL diagnostic | 지역 단위, 기준일, 소비 단위 |
| 인기관광지 현황 | 연령대별 관광지 관심과 대상 고객 제안 | MySQL attraction dimension/fact | 관광지 ID, 지역 연결, 중복 관광지 |
| 중심-연관 관광지 지도 | 관광지 네트워크·연계 가능성 근거 | MySQL edge table | 중심/연관 방향, 관광지 ID, 기간 |
| 지역별 관광지 관광객 현황표 | 관광지별 내·외국인 월간 방문객 | MySQL attraction monthly fact | 2행 헤더, 2023~2026 월 펼치기, 행정명칭 |
| out.csv | 관광지 현황 통합본 후보 | 중복 검토 후 결정 | 16개 지역 파일과 hash·행 비교 |
| 방문자기준지역방문현황 | 현재 빈 폴더 | 미사용 | 새 자료 추가 여부 감시 |

## 기획서 활용 예시

```text
월별 지역 사실
  + 전국·비교 지역 기준
  + 외래객 구성
  + 연령대별 인기 관광지
  + 관광지별 실제 방문 추이
  + 중심·연관 관광지 연결 구조
  + 저장된 ML 전망(품질 gate 통과 시만)
  + 공식 사업 문서 RAG
  → 문제/기회 근거
  → 서로 다른 전략 후보
  → 실행 가능성·예산·KPI 검수
  → 최종 기획서
```

관광지 네트워크 자료가 있다고 해서 동선 연결 전략을 항상 추천하지 않는다. 소비·체류·외래객·계절성·공식 사례를 함께 비교하고, 후보 전략 중 근거와 실행성이 가장 높은 경우에만 사용한다.

## 계속 추가되는 자료 처리

1. `source_repository_inventory.py`가 새 파일과 변경 파일을 탐지한다.
2. 신규 파일은 `needs_review` 상태로 등록한다.
3. schema·출처·지역코드·기간·단위를 검사한다.
4. 기존 source와 중복 여부를 확인한다.
5. 검증을 통과한 자료만 processed/MySQL/RAG 중 알맞은 계층으로 이동한다.
6. 영향받은 지역·기간만 다시 전처리하고 필요한 모델만 재학습한다.
