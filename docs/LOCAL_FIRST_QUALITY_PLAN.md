# 로컬 우선 기획 품질 개선 계획 — 2026-09-02

## 목표와 범위

사용자가 승인한 방향은 **Qwen·Gemma를 적극 활용하면서 기획의 근거성과 실행성을 우선하고, OpenAI는 중요한 공식 근거 보강·독립 검수에 한정**하는 것이다. 작업 대상은 TP2-3뿐이다. 모델 교체만으로 기획 품질 향상을 주장하지 않는다.

이번에는 아래 1차 구현을 진행했다. 개인 Ollama의 합성 자료 도구·JSON 점검은 완료했으나, 실제 기획 생성, 비용 비교 평가, PPT 전면 재편집은 아직 완료한 것으로 보지 않는다. 기존 팀 작업·원본 데이터·저장 보고서는 삭제하지 않는다.

## 1차 구현의 실행 순서

1. 개발 PC AI Server가 개인 노트북 Ollama의 Qwen/Gemma 연결·모델 태그를 확인한다. 실패하면 유료 조사를 시작하지 않는다. 이 확인은 추론/GPU 성능 보장이 아니다.
2. Python이 관측값·MySQL 지역 비교·저장 ML 전망을 구성한다. `decision_facts.py`가 비교 방향·기간·기존 ML 집계법을 정리한다. 수치 학습/재계산을 LLM에게 맡기지 않는다.
3. 공식 API·저장 문서·검수 사례를 모은다. 로컬 우선 RAG 조회는 유료 쿼리 임베딩 없이 키워드 방식으로 수행하며, 의미 유사도 검색으로 표시하지 않는다. 제공 PDF는 `official_reference_chunks.jsonl`의 페이지 청크까지 무료 키워드로 조회한다. Chroma 의미검색은 별도 1회 색인 작업 뒤에만 사용하며, 생성 중 새 임베딩 호출은 하지 않는다.
4. Qwen이 비교·전망·사례를 도구로 읽고 후보 2~3개의 실행 원리·적용 차이·비용·위험을 비교한다. 저장 사례가 부족하면 공식 웹 보강 후 적용성을 한 번 재검토한다.
5. Gemma가 선택 근거를 실행안으로 작성한다. 문제/전망 → 사례/비교 → 해결 원리 → 5단계 일정 → 예산 → 측정·중단 기준을 연결한다.
6. 코드 점검 + Qwen 사전 검수. 미달이면 Gemma 수정 최대 1회 → Qwen 재검수. 결정적 오류·major/critical·82점 미만은 승인하지 않는다.
7. 로컬 검수 통과 결과만 OpenAI 독립 최종 검수 1회. 최종 미달/실패는 미승인 초안이다. 작성 후 검수 연결 실패에도 기존 초안은 보존한다.

## 비용 경계

- 생성 1건이 공유하는 Router의 **OpenAI Responses 요청 시도 최대 3회**: 지역 조사 최대 1회, 사례 조사 또는 보강 최대 1회, 최종 검수 최대 1회.
- 실패한 요청도 상한에 포함한다. 병렬 요청도 await 전에 횟수를 예약한다. 로컬 우선 모드에서 OpenAI 토큰 부족 자동 재호출은 하지 않는다. 최초 단계별 출력 상한/추론 강도는 유지한다.
- 이는 정액/원화 예산이나 웹검색 내부 도구 실행 횟수의 상한이 아니다. 사용자는 같은 생성을 다시 요청할 수 있고, 다른 채팅 요청은 별도 실행이다. 가격·총청구액은 별도 검증해야 한다.
- 연결 실패를 유료 전체 작성으로 바꾸지 않는다. `hybrid`는 기존 동작을 유지하는 명시적 선택이다.
- 로컬 도구 선택은 일반적으로 2회(후보 비교 Qwen은 사례 다양성 확인을 위해 3회, 회당 최대 3함수)다. 잘못된 인자는 실행하지 않고 허용 Schema를 돌려줘 교정용 1회만 추가한다. 긴 초안은 페이지 수에 따라 늘리되 교정 포함 최대 8회다. JSON 형식 교정은 최대 1회. 문맥/최종 출력 상한을 몰래 낮추거나 원문을 자르지 않는다.
- Ollama는 도구 선택과 최종 JSON에 `think=false`, 낮은 temperature, 15분 모델 유지 설정을 사용한다. 이는 불필요한 숨은 출력·재로드를 줄이기 위한 호출 조정이며, Qwen/Gemma를 지역 자료로 fine-tuning한 것이 아니다.
- OpenAI 없는 신규 실시간 웹검색 도구는 아직 없다. Qwen이 사용할 수 있는 검색은 현재 요청의 수집 자료 검색이다. 별도 검색 서비스/허용 API 선정 없이 크롤링을 추가하지 않는다.
- 관리자 학습용 ML/OpenAI/React 챗봇의 기존 전용 OpenAI 경로는 이번 생성 흐름 개선과 별개다. 모든 기능이 무료 또는 로컬로 전환됐다는 뜻이 아니다.

## 다음 검증 단계와 합격 기준

### A. 실제 개인 GPU 점검

2026-09-02 합성 자료 점검에서 Qwen `qwen3:14b`와 Gemma `gemma4:26b`의 실제 원격 도구 조회 및 JSON 반환을 확인했다. 초기 Qwen의 불필요 인자 문제는 제한된 교정으로, Gemma의 작은 테스트 출력 상한 문제는 운영용 출력 상한으로 재검증했다. 소요 시간은 해당 테스트에서 약 33초/79초이며 전체 기획 생성 시간을 뜻하지 않는다. GPU/CPU 메모리 점유는 별도로 측정하지 않았다.

합성 답변에는 과거 월 실행 일정·KPI 분모·임의 목표값 문제가 관찰됐다. 따라서 도구 성공을 기획 품질 통과로 보지 않고, 과거 월 집행 차단 검사와 KPI 지침을 추가했다. 실제 강남 기획안에 대한 독립 검수와 담당자 비교 평가는 여전히 필요하다. 테스트 스크립트는 `ai_server/app/scripts/check_local_agent_smoke.py`이며 유료 Provider를 만들지 않는다.

개인 노트북 Ollama 연결 후 두 모델 각각의 함수 호출·JSON 출력·실제 모델 태그를 확인한다. ACTIVE 표시만으로 사용 성공 판정을 하지 않는다. 네트워크/VRAM/응답시간에 따라 문맥·로컬 출력 예산을 조정하려면 먼저 실패 기록을 확보한다.

### B. 동일 입력으로 품질 비교

강남의 같은 관측월·조건·근거 묶음으로 로컬 우선 결과를 검토한다. 예산 확정/미정, 일정 고정/미정, 데이터 부족, 비교 지역 변경을 포함한다.

- 출처·기간·단위·비교 방향 오류 0건
- 근거 없는 사업 효과 수치 0건, 확보되지 않은 자원 확정 표현 0건
- 운영 원리가 다른 후보 비교와 탈락 이유가 있음
- 사례의 실제 운영 방식·지역 적용 차이·측정 한계가 설명됨
- KPI 분자/분모·비교군·측정 주기·성공/중단 기준이 성립함
- 모델·Provider·도구·토큰·실패·유료 요청 사유가 기록됨
- 기존 결과보다 나아졌는지는 담당자 비교 평가로 판단하며, 테스트 코드 통과나 LLM 점수를 품질 향상 증명으로 대체하지 않음

### C. 사업효과 정량화

ML 자연추세와 “사업 시행 시” 시나리오를 분리한다. 효과 추정에는 실제 운영일/비교군/참여·결제/중복·대체소비·측정기간 자료가 필요하다. 타지역 월간 수치만으로 강남의 소비 증가율을 인과 추정하지 않는다. 데이터가 없으면 손익분기점·필요 전환율·확인할 가정과 수집 계획을 제시한다.

### D. PPT 내용 맞춤과 시각 검증

승인된 편집 가능 템플릿은 유지한다. 장표는 핵심 판단, 자연추세, 후보/사례 적용 차이, 솔루션, 실행 일정, 예산, KPI/시나리오 순으로 정리한다. 특히 현재 출력 코드의 월 목록 슬라이스와 실제 선택 기간을 대조한다. 표·그래프·본문 숫자 일치와 모든 슬라이드의 넘침/줄바꿈을 렌더로 검사한 후 전달한다. 이번에 새 PPT를 생성하거나 레이아웃 완료를 선언하지 않는다.
