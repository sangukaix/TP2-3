# 모델 호출 없는 전체 코드 점검 — 2026-09-12

## 범위와 결론

React/Vite 경로·페이지 분리·API 연결, 생성 작업 복원·수정·저장, 사례 조사 입력과
비교 집계, 데이터/ML 파이프라인 및 문서 출력 계약을 코드와 모의 테스트로 점검했다.
실제 Qwen·Gemma·OpenAI 호출, 연결 확인, 새 라이브러리 설치는 하지 않았다.
운영 MySQL 쓰기·재학습·기존 보고서 갱신도 하지 않았다.
이 결과는 모든 지역의 실제 기획 품질이나 장애 없는 운영을 보증하지 않는다.

## 수정한 문제

1. **외부 글꼴 실패가 빈 화면으로 연결됨**: 공통 CSS의 Google Fonts `@import`가
   실패하면 Vite의 페이지 CSS preload도 실패했다. 선택적 글꼴을 HTML의 별도 link로
   분리해 기본 글꼴로 열리게 했다. React 오류 경계는 청크/화면 오류 시 새로고침 경로를 제공한다.
2. **브라우저 저장소와 서버 결과의 결합**: 지역 선택·작업 ID 저장/삭제 실패가
   화면을 깨지 않게 처리했다. 새 작업은 지역 코드/이름과 작업 ID를 `/strategy` 주소에
   전달하며 완료·실패 시 주소에서 제거한다. 브라우저 캐시에 실패해도 수정은 React 상태에
   반영하고, 확정 저장은 MySQL 응답을 기준으로 처리한다. 주소에는 본문·키를 넣지 않는다.
   브라우저 조건 임시저장 자체가 실패하면 기존처럼 생성 전에 안내한다.
3. **사례 지역 수 과대 집계**: '인천 전역'과 '인천 송도·월미도'를 서로 다른 지역으로
   세던 문제를 수정했다. 도에서는 첫 시·군, 광역시에서는 명시된 구·군을 비교 단위로 쓰며,
   광역시 전체와 포함 구는 독립 지역으로 중복 집계하지 않는다. 이 집계는 행정구역/성과의
   사실성을 자동 검증하는 모델이 아니다. 조사 캐시 계약 v6으로 이전 집계 재사용을 막았다.
4. **개발 포트 불일치**: Backend CORS에 `localhost:5176`과 `127.0.0.1:5176`을 추가했다.
   기본 Vite 프록시 구조와 배포 경로는 유지한다.
5. **구형 출력 테스트**: 승인된 산출 근거 2장 추가 및 v19 렌더러 변경을 반영하지 못한
   3개 테스트를 현재 계약으로 갱신했다. 출력 코드·확정 PPT 디자인은 바꾸지 않았다.

## React 구조와 정리

- `src/main.jsx → App.jsx → routes.js → pages` 진입, 페이지별 lazy/Suspense,
  `components` 공통 UI, `features/planning` 입력·수정 규칙, `api/dashboardApi.js` 서버 연결을 확인했다.
- 현재 이동 방식은 전체 페이지 탐색이므로 별도 react-router 없이 명시적 경로 매핑을 사용한다.
  경로 별칭·잘못된 주소 처리·Vite 프록시·production 분할 빌드가 있다. 라우터 라이브러리를 추가하지 않았다.
- 사용처가 없는 동기 `getAiStrategyReport`와 그 안의 자동 샘플 우회 경로를 제거했다.
  현재 생성은 백그라운드 jobs API를 사용한다. 서버의 별도 진단/sample API는 유지한다.
- 내용 없이 import만 하던 `src/index.css`를 제거하고 HTML 언어/탭 제목을 한국어 서비스로 맞췄다.
- 구버전 PPT/layout 모듈은 현재 렌더러가 참조하므로 삭제하지 않았다.
  `.chart-data-*`에도 PPT·수치 스냅샷이 있으므로 빈 임시 폴더로 간주해 삭제하지 않았다.
  기존 미커밋 변경·원자료·가공 데이터·저장 모델·문서 결과는 보존했다.
