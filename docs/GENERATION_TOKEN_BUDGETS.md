# 기획안 출력 토큰 설정 — 2026-09-02

## 현재 설정

아래 값은 OpenAI 한 번의 **내부 추론 + 출력 상한**이다. 매번 이만큼 사용하라는 뜻이 아니다.
모델명과 추론 강도는 바꾸지 않았다. 실제 성공률은 다음 기획안 테스트에서 확인해야 한다.

| 단계 | 이전 상한 | 최초 상한 | 토큰 부족 시 1회 재시도 | 추론 |
| --- | ---: | ---: | ---: | --- |
| 지역 근거 조사 | 8,000 | 10,000 | 16,000 | low |
| 공식 사례 조사 | 10,000 | 16,000 | 24,000 | medium |
| 지역 적용 가능성 검토 | 7,000 | 16,000 | 24,000 | medium |
| 기획안 본문 작성 | 16,000 | 24,000 | 32,000 | high |
| 품질 미달 기획안 수정 | 14,000 | 20,000 | 28,000 | medium |
| 최초 검수 / 재검수 | 5,500 | 12,000 | 20,000 | high |

- 개인 GPU의 Qwen 적용 검토는 7,000, Gemma 본문은 16,000, 수정은 14,000으로 유지한다. `local_only` 실험 검수도 기존 5,500이다.
- 로컬 근거 도구의 함수 선택은 본문과 분리된 512토큰 상한이다. 필수 근거 사전조회가 완료된 경우에만 선택 단계 미완료를 기록하고 본문 작성으로 진행한다. 본문 출력 상한을 늘리거나 잘린 본문을 이어 붙이는 정책이 아니다.
- 로컬 최종 JSON이 미완료이면 같은 역할별 상한으로 1회만 처음부터 재생성한다. 잘린 응답은 프롬프트에 다시 넣지 않으며, 두 번째 미완료는 실패한다. 로컬 GPU 시간은 늘 수 있지만 OpenAI 비용은 발생하지 않는다.
- 로컬 문맥 한도를 넘으면 Hybrid는 기존처럼 OpenAI로 폴백한다. 클라우드 출력 상한 확대로 GPU 문맥/VRAM 설정을 함께 늘리지는 않는다.
- 학습용 챗봇의 800토큰 상한과 일반 챗봇 정책은 변경하지 않았다.

## 로컬 우선 예외 (D-063)

`local_first`에서는 아래 OpenAI 자동 재호출을 하지 않는다. 최초 출력 상한과 추론 강도는 유지하고, 실패한 호출도 생성당 최대 3회 상한에 포함한다. 초안 작성·수정은 Gemma, 1차/재검수는 Qwen, 통과 후 최종 검수만 OpenAI이다. 연결 실패 시 유료 대체하지 않는다. 이는 품질 기준을 낮추는 대신 미완료/미승인을 명시적으로 반환하는 선택이다. [세부 계획](LOCAL_FIRST_QUALITY_PLAN.md).

## 언제 재시도하는가 (hybrid / openai_only)

`완료 → 그대로 사용` / `incomplete + max_output_tokens → 같은 단계만 큰 상한으로 1회 다시 생성`.

- 기존 입력·공식 출처·사용자 조건·모델·추론 강도·JSON Schema를 유지한다. 앞 단계 전체를 재실행하거나 부분 JSON을 이어 붙이지 않는다.
- 두 번째 응답도 미완료이면 안전하게 실패 처리한다. 잘린 기획서를 완성본으로 통과시키지 않는다.
- 인증·결제 한도·통신·시간 초과·콘텐츠 필터·스키마 오류는 이 정책으로 반복하지 않는다.
- 기획 단계의 OpenAI HTTP 대기는 요청당 600초이다. 1회 재시도까지 실행되면 해당 단계의 요청 대기시간만 최대 20분이며, 별도 전후처리 시간이 추가된다.
- 재시도는 입력·출력을 다시 처리하므로 비용이 늘 수 있고 공식 웹 검색도 다시 수행될 수 있다. 이는 성공 보장·무제한 실행 정책이 아니다.
- Reviewer 품질 미달 시 Planner를 한 번 수정하는 기존 정책은 그대로 유지한다. 토큰 부족 회복과 품질 수정은 서로 다른 절차다.

## 사용량과 확인 경로

`GET /ai/v1/llm/trace`에서 각 이벤트의 `attempts`, `retry_count`, `usage`, `error_code`를 확인한다.

- `usage`는 성공/미완료 시도들의 보고된 사용량 합계다. `reasoning_tokens`는 `output_tokens`에 포함되므로 다시 더하지 않는다.
- `usage_reported=false`는 미확인이지 무료/0토큰이라는 뜻이 아니다. 실패한 OpenAI 폴백도 기록한다.
- trace는 현재 프로세스 메모리의 최근 기록이며 서버 재시작 시 사라진다. 청구서나 계정 전체 비용을 대신하지 않는다.
- API 키·프롬프트·원문 근거·실제 응답 전문은 trace에 보관하지 않는다.

## 코드 위치

- `ai_server/app/agents/{evidence,case_study,transferability,planner,reviewer}_agent.py`: 단계별 숫자와 추론 강도.
- `ai_server/app/llm/models.py`: 최초/재시도/로컬 출력 상한의 공통 요청 필드.
- `ai_server/app/openai_responses.py`: 토큰 부족 판정, 1회 재시도, 스키마 검증, 사용량 합산.
- `ai_server/app/llm/router.py`: 로컬·OpenAI 예산 분리와 성공/실패/폴백 trace.
- `ai_server/app/llm/local_agent.py`: 512토큰 도구 선택과 필수 근거 완료 조건의 제한적 진행.
- `ai_server/test_openai_token_recovery.py`: 유료 API 없이 실제 HTTP 응답 형태를 재현한 회귀 테스트.

## 검증

검증 명령: `python -m unittest ai_server.test_openai_token_recovery -q` 및 `python -m unittest discover -s ai_server -p 'test_*.py' -q`.
실제 유료 기획안은 이번 변경 검증에서 생성하지 않는다. 시간·비용·완성도는 별도 실생성 결과로 평가한다.

- 토큰 회복 전용 테스트 13개 통과: 성공 시 1회, 토큰 부족 시 정확히 2회, 두 번째 실패 시 중단,
  입력·스키마·웹 허용 도메인 유지, 인증/결제/시간 초과 재시도 금지, 실패 사용량 합산, Hybrid 폴백 실패 추적.
- 전체 AI 서버 테스트 107개 통과. 가짜 PDF·미설정 DB 오류 경로의 로그와 기존 라이브러리 deprecation 경고는 테스트 실패가 아니다.
- Python 관련 20개 모듈 구문 검사와 `git diff --check` 통과. Frontend 소스와 ML 학습 로직은 수정하지 않아 별도 빌드/재학습은 수행하지 않았다.
- 실행 중 AI 서버의 health·강남 dashboard·새 trace 계약과 Frontend의 `/ai/health` 프록시가 모두 HTTP 200.
  브라우저에서 새 생성 요청을 해야 바뀐 정책으로 실행된다. 과거 실패 기획안을 자동 재실행하지 않았다.
