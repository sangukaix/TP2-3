# 기획안 생성·ML·문서 출력 재검토

TP2-3만 점검·수정했다. 원자료·Joblib·MySQL 데이터·팀원 변경은 유지했고, 유료 OpenAI 생성/임베딩과 재학습은 수행하지 않았다.

## 수정한 문제

| 문제 | 조치 |
|---|---|
| 6개월 기획인데 PPT는 3개월, Word는 내부 예측 첫 6개월 선택 | `report_projection.py`에서 최종 기획 연월/선택 후보를 함께 사용. 관측 공백 월 제외, 부분 전망 표시 |
| Word/PPT의 목표 첫 달 산식 불일치 | 최종 월 목표까지 균등 적용하는 공통 산식. 입력 없는 증가율 생성 금지 |
| 빈 목표 객체에 +5%/+8% 자동 입력 | 두 비율을 명시한 경우만 허용, 빈 객체는 422 |
| 문서 렌더링·사진 다운로드 중 API 정체 | 스레드 렌더링, Matplotlib 공유 상태 잠금 |
| Word 실패로 PPT도 생략 | 형식별 실패 분리, 본문 보존, 상태 경고 |
| production 결제 오류가 샘플 성공으로 바뀜 | 운영 환경 백그라운드 작업의 샘플 대체 금지 |
| 출력 중 본문 수정 시 구형 파일을 새 지문으로 저장 | 실제 렌더 입력 지문을 캐시에 전달·검증 |
| 화면의 미검수 상태가 문서에는 없음 | 초안·미검수·오프라인·통과 상태를 표지에 표시 |
| ML 연결과 성능 우수 혼동 | model_reliability로 Test/재귀 열세·계절 기준선을 구분 |
| 소비/방문 비율을 실제 객단가로 오해 | 분자·분모 표본 일치 미검증 표시와 Agent 해석 제한 |

12장 템플릿·네이티브 차트는 유지했다. 렌더 버전을 갱신해 다음 다운로드 시 오래된 캐시를 재생성한다. 모든 저장 문서를 일괄 덮어쓰지는 않았다. 이번 검증은 생성 코드/데이터 계약이며 새 실사용 문서 전체의 시각 검수는 별도다.

## 실제 데이터와 모델

- 강남구 demand-v3.0: 원자료 2024.01~2026.07, 최신 확정 관측 2026.07.
- MySQL 전국 비교 조회 성공: 공통 기간 2025.07~2026.06, 비교 지역 5개.
- 공식 사례 레지스트리 6건, 허용 도메인 통과. 전국 모든 사업을 검색/학습했다는 뜻은 아니다.
- Chroma 문서 수·검색 적합성은 이번에 재측정하지 않았다.

| Target | 모델 | Test MAE / 계절 기준선 MAE | 판단 |
|---|---|---|---|
| 방문자 | RandomForestRegressor | 537,513.5 / 673,789명 | Test 개선, 재귀 1·2개월은 기준선보다 나쁨 |
| 관광소비 | seasonal-naive | 24,906,220,750 / 동일 원 | 전년 동월 기준선 자체 |

| 내비게이션 검색 | seasonal-naive | 62,521.5 / 동일 건 | 기준선 자체 |

Validation 전용 모델 선택을 유지하고 Test를 보고 재선택하지 않았다. 재귀 평가는 horizon별 origin 두 개로 강한 일반화가 어렵다. 3개월 초과 예측 거리는 탐색값이다. 7월 관측으로 9~11월을 전망하면 마지막 달은 검증 거리 밖이다.

## 추가 ML 우선순위 — 미학습

1. 기간별 rolling-origin 평가 확대: 충분한 이력부터 1·3·6개월 재귀/직접 전망 비교. Validation 선택, 독립 Test 유지. 표본 부족 시 검증 완료로 표시하지 않는다. [TimeSeriesSplit](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)
2. 불확실성 구간: 분위수/오차 기반 구간의 coverage·폭을 검증한 뒤 도입. MAE를 95% 신뢰구간으로 바꾸지 않는다. 전국 패널도 달력 기준 분리·지역 홀드아웃 필요. [공식 시계열 예제](https://scikit-learn.org/stable/auto_examples/applications/plot_time_series_lagged_features.html)
3. 업종별 소비 전망: 동일 분류·단위·표본의 지역×월×업종 이력을 검증. 최신 관측 비중 적용은 업종별 독립 ML이 아니다.
4. 사업 효과 평가: 시행일·참여자·예약/입장/결제·환불·비용·비교집단 자료 필요. 현재 자연추세만으로 ‘패스를 하면 소비 X% 증가’라는 인과효과는 추정할 수 없다.

## 기획서 보강 우선순위

- 같은 실행 기간의 자연추세·관측 문제·약한 모델의 한계를 첫 판단에 연결.
- 공식 사례의 운영 요소와 강남에서 유지·변경·제외할 요소, 필요한 계약·자료를 나란히 제시.
- 서로 다른 실행 원리의 후보 2~3개를 비용·준비기간·측정 가능성으로 비교.
- 참여 규모×이용완료율×추가 결제액 같은 **측정할 가정**을 제시하되 근거 없는 입력값은 채우지 않음.
- 담당 역할·월·산출물, 수량×확인된 단가, KPI 분자/분모·기준선·비교집단·수집 방법.

일부는 이미 프롬프트/스키마에 있다. 실제 새 강남구 결과가 충족하는지는 실전 평가가 필요하다. 지시문이나 단위 테스트는 기획 품질 개선의 증명이 아니다.
