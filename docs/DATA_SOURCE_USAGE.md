# 데이터 출처·사용 현황

이 문서는 서비스에서 사용하는 원본 ZIP과 Open API의 역할, 현재 연결 상태를 함께 기록한다. 새 ZIP 또는 Open API를 실제 화면·분석·보고서에 추가하면 **이 문서, `README.md`, 필요 시 `requirements.txt`를 같은 작업에서 갱신**한다.

## 1. 역할 분리

```text
한국관광 데이터랩 ZIP
→ 월별 방문·관광소비·체류·관심도 등 수치 분석
→ 전처리·ML 학습·MySQL 사실 지표·AI 보고서의 수치 근거

관광 Open API
→ 관광지·관광자원·무장애·캠핑·연관 관광지 등 지역 맥락
→ 지역 인프라 대시보드와 RAG/AI 전략의 공식 보조 근거

VWorld Open API
→ 시도·시군구 행정구역 경계 지도
```

ZIP의 월간 수치와 Open API의 관광지 설명·자원 정보는 같은 목적의 데이터가 아니다. 두 자료를 지역코드·기준월·정의 검증 없이 임의로 합치지 않는다.

인천광역시는 2026년 7월 1일 기존 서구가 서해구·검단구로 개편되었다. 현재 보유한 서구 원자료의 최신월은 2026년 6월이므로, 지도에는 두 현재 경계를 합친 `인천광역시 서구 (2026.06 원자료 기준)` 선택 항목을 별도로 표시한다. 이는 개편 후 두 구의 통계를 합산한 값이 아니며, 개편 전 원자료의 공간 범위를 보여 주기 위한 호환 표시다.

## 3. 한국관광 데이터랩 ZIP

원본은 수정하지 않고 아래 경로에 보관한다.

```text
data/raw/{광역시도}/{시군구}/{데이터종류}/{기간}/원본.zip
```

강남구의 현재 확보 범위는 `2025-08 ~ 2026-07`이며, 다음 ZIP을 보관한다.

| 데이터 종류 | 대시보드·분석 활용 | 우선순위 |
| --- | --- | --- |
| 방문자 | 월별 외지인 방문자 수, 유입 지역, 내비게이션 검색량 | 필수 |
| 관광소비 | 월별 외지인 관광소비액, 업종별 소비 패턴 | 필수 |
| 숙박_체류시간 | 숙박 방문 비율, 평균 숙박일수 | 필수 |
| 소셜미디어 | SNS 언급량과 관심도 추이 | 높음 |
| 유입유출지역 | 방문자 기준지역·유입권역 분석 | 높음 |
| 인기관광지 | 인기 관광지·관광지별 확인 항목 | 보조 |
| 지역집중률 | 관광지 집중도와 분산 가능성 | 보조 |
| 유사지역 | 비교 후보 탐색 | 보조 |
| 종합분석 | 자료 간 요약·검증 참고 | 보조 |

### 주의할 지표 정의

- 방문자·숙박 지표는 이동통신 기반 **외지인** 기준일 수 있다.
- 상단 카드의 방문자 수는 `순 방문자수` 표를 사용한다. 숙박 비율의 분모와 동일한 월간 고유 방문자 수이며, 체류일수만큼 중복되는 `방문자 수(연인원)`와 혼용하지 않는다.
- 강남구 상단 카드·AI 보고서의 관광소비 지표는 카드 기반 **외지인 관광소비** 표를 사용한다. 현지인 소비가 섞인 내국인 전체 표보다 관광객 유입 분석에 적합하다.
- 그래프 아래의 관광소비·체류 진단은 `관광소비 추이_외지인`의 업종대분류별 소비액, `순 방문자 수 및 숙박 비율`, `평균 숙박일` 표의 최신 기준월 값으로 계산한다. 업종별 소비액은 전체 외지인 관광소비액 대비 비중이며, 서로 다른 업종 비중을 합산해 매출 증가로 해석하지 않는다.
- 외지인 소비도 방문 목적을 완전히 판별한 실제 매출이 아니라 카드 기반 관광소비 추정치이므로, 현금·계좌이체 등을 포함한 지역 전체 매출로 해석하지 않는다.
- 따라서 두 값을 단순히 나눠 `1인당 소비액`이라고 표시하지 않는다. 동일 모집단·기간의 분모가 검증된 경우에만 계산한다.
- ML과 정식 대시보드는 `region_code + year_month`가 검증된 행만 결합한다.

## 4. Open API 활용 계획

| API 또는 제공기관 | 사용할 정보 | 화면·AI 활용 위치 | 상태 |
| --- | --- | --- | --- |
| VWorld WFS | 시도·시군구 경계 | 지역 선택 지도 | 사용 중 |
| 한국관광공사 국문 관광정보 서비스 | 관광지 기본 정보·위치·분류 | 지역 선택 `지역 정보 상세보기` 팝업, 지역 전략 보조 근거 | `areaCode2` → `areaBasedList2` 서버 조회 연결. 인증키·서비스 활용신청·응답 범위는 환경별 확인 필요 |
| 지역별 관광 수요 강도 | 지역별 수요 보조지표 | 지역 진단 보조 신호 | 응답 정의 검증 후 연결 |
| 지역별 관광자원 수요·다양성 | 관광자원 수요·다양성 | 지역 자원 진단·전략 근거 | 응답 정의 검증 후 연결 |
| 관광지 집중률 방문자 추이 예측 | 집중도 관련 보조 정보 | 혼잡·분산 전략 보조 근거 | 응답 정의 검증 후 연결 |
| 기초지자체 중심 관광지·연관 관광지 | 관광지 목록·연계 후보 | 지역 자원 카드·AI 보고서 근거 | operation 검증 후 연결 |
| 고캠핑·무장애 여행·두루누비 | 특화 관광자원 | 접근성·체험·숙박 연계 정보 | 필요 지역부터 연결 |
| 관광사진·공모전 수상작 | 대표 이미지·소개 보조 | 관광지 카드의 시각 자료 | 저작권·이용 조건 확인 후 사용 |

공공 API 키는 Backend 또는 AI Server의 `.env`에서만 읽는다. `VITE_` 접두사 변수, React 소스, Git 커밋, 화면 및 로그에 키를 넣지 않는다.

## 5. 새 데이터 추가 절차

1. 원본 ZIP을 `data/raw/`의 지역·종류·기간 폴더에 원본 파일명 그대로 저장한다.
2. 출처 URL, 다운로드일, 기간, 단위, 지역단위, 파일 SHA-256을 `SOURCE_REGISTRY.csv`에 기록한다.
3. CSV 컬럼·인코딩·지역코드·기준월·결측을 확인한 뒤에만 `data/processed/`로 변환한다.
4. 실제 화면 또는 분석에 연결할 때 이 문서의 **현재 실제 연결 상태**와 **Open API 활용 계획**을 갱신한다.
5. 새 Python/Node 라이브러리를 코드에 추가했다면 `requirements.txt` 또는 `frontend/package.json`도 같은 변경에 갱신한다.

## 6. 다음 연결 우선순위

1. 지원 지역 원본 → 재현 가능한 `data/processed/` 전처리 → MySQL 월별 지표 적재
2. 관광 Open API로 관광자원·인프라 보조 근거 연결
3. 검수된 공식 문서·사례의 ChromaDB 색인 확대
4. 여러 시군구·2~3년 이상 공통 월간 데이터 확보 후 seasonal-naive baseline과 후보 ML 모델 비교
