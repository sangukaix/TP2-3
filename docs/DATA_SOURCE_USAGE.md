# 데이터 출처·사용 현황

이 문서는 서비스에서 사용하는 원본 ZIP과 Open API의 역할, 현재 연결 상태를 함께 기록한다. 새 ZIP 또는 Open API를 실제 화면·분석·보고서에 추가하면 **이 문서, `README.md`, 필요 시 `requirements.txt`를 같은 작업에서 갱신**한다.

## 1. 역할 분리

### 사용자 사업 여건·참고자료 (2026-08-28 추가)

- 입력 위치: `/planning`. 예산·기간·자원·필수 제약·현장 의견·선호는 **사용자 제공 조건**이지 공식 관측 사실이 아니다.
- TXT/MD/DOCX 텍스트는 `POST /ai/v1/planning/reference`에서 기존 python-docx로 읽는다. 외부 API 호출·디스크 원본 저장·공용 ChromaDB 등록은 하지 않는다.
- 문서 텍스트는 브라우저 초안과 생성 결과의 조건에 포함되며, 사용자가 생성/채팅을 요청하면 OpenAI 입력으로 전달된다. 개인정보·비공개 민감정보는 첨부하지 않는다.
- 공식 ZIP·API 수치와 별도로 다섯 Agent와 챗봇에 전달한다. 공식 자료와 충돌하는 주장은 확인이 필요한 현장 정보로 취급한다. 타 지역 성과를 이 지역의 보장 성과로 바꾸지 않는다.
- 새 외부 API·라이브러리 없음. 기존 requirements 유지.

```text
한국관광 데이터랩 ZIP
→ 월별 방문·관광소비·체류·관심도 등 수치 분석
→ 전처리·ML 학습·MySQL 사실 지표·AI 보고서의 수치 근거

관광 Open API
→ 관광지·관광자원·무장애·캠핑·연관 관광지 등 지역 맥락
→ 지역 인프라 대시보드와 RAG/AI 전략의 공식 보조 근거

VWorld Open API
→ 시도·시군구 행정구역 경계 지도
```

ZIP의 월간 수치와 Open API의 관광지 설명·자원 정보는 같은 목적의 데이터가 아니다. 두 자료를 지역코드·기준월·정의 검증 없이 임의로 합치지 않는다.

### 새 기획안 생성 전 최신성 보호 (2026-09-04 추가)

- AI Server의 `GET /ai/v1/demo/{region_code}/generation-readiness`와 전략기획 생성 API는 마지막 확정 관측월을 함께 확인한다. 현재 진행 중인 월은 미완성 자료이므로 제외하고, 직전 완료월까지 **3개월 이상**의 공백이 있으면 새 기획안 생성만 `DATA_REFRESH_REQUIRED`로 차단한다.
- 안내에는 실제로 필요한 원자료 시작·종료월과 `원자료 적재 → 기간·지역 코드·단위 검증 → ML 재학습 → 계절 기준모델 비교` 순서를 표시한다. 새 자료가 들어왔어도 저장 모델 지문이 다르면 기존 ML 근거는 그대로 사용하지 않는다.
- 대시보드, 저장된 기획안, 이미 생성된 Word·PowerPoint의 열람·다운로드는 당시 확정된 사실을 보여 주는 기능이므로 이 차단 대상이 아니다.

## 3. 한국관광 데이터랩 ZIP

수동 보관 원본은 수정하지 않고 아래 경로에 둔다. 팀 공유폴더와 기존 수동 원본의 복제본은 `data/raw/`를 바꾸지 않고, SHA-256 관계가 기록되는 불변 snapshot 경로에 별도로 둔다. 활성 ML 카탈로그는 후자만 사용한다.

```text
data/raw/{광역시도}/{시군구}/{데이터종류}/{기간}/원본.zip
data/source_snapshots/{광역시도}/{시군구}/{데이터종류}/원본.zip
data/source_snapshots/서울특별시/서울특별시_강남구/supplemental_202607/원본.zip
```

강남구의 현재 확보 범위는 `2024-01 ~ 2026-07`이며, 2024~2026 연도별 묶음 ZIP과 최신 2026년 7월 다운로드 ZIP을 함께 보관한다.

| 데이터 종류 | 대시보드·분석 활용 | 우선순위 |
| --- | --- | --- |
| 방문자 | 월별 외지인 방문자 수, 유입 지역, 내비게이션 검색량 | 필수 |
| 관광소비 | 월별 외지인 관광소비액, 업종별 소비 패턴 | 필수 |
| 숙박_체류시간 | 숙박 방문 비율, 평균 숙박일수 | 필수 |
| 소셜미디어 | SNS 언급량과 관심도 추이 | 높음 |
| 유입유출지역 | 방문자 기준지역·유입권역 분석 | 높음 |
| 인기관광지 | 인기 관광지·관광지별 확인 항목 | 보조 |
| 지역집중률 | 관광지 집중도와 분산 가능성 | 보조 |
| 유사지역 | 비교 후보 탐색 | 보조 |
| 종합분석 | 자료 간 요약·검증 참고 | 보조 |

### 주의할 지표 정의

- 방문자·숙박 지표는 이동통신 기반 **외지인** 기준일 수 있다.
- 상단 카드의 방문자 수는 `순 방문자수` 표를 사용한다. 숙박 비율의 분모와 동일한 월간 고유 방문자 수이며, 체류일수만큼 중복되는 `방문자 수(연인원)`와 혼용하지 않는다.
- 강남구 상단 카드·AI 보고서의 관광소비 지표는 카드 기반 **외지인 관광소비** 표를 사용한다. 현지인 소비가 섞인 내국인 전체 표보다 관광객 유입 분석에 적합하다.
- 그래프 아래의 관광소비·체류 진단은 `관광소비 추이_외지인`의 업종대분류별 소비액, `순 방문자 수 및 숙박 비율`, `평균 숙박일` 표의 최신 기준월 값으로 계산한다. 업종별 소비액은 전체 외지인 관광소비액 대비 비중이며, 서로 다른 업종 비중을 합산해 매출 증가로 해석하지 않는다.
- 외지인 소비도 방문 목적을 완전히 판별한 실제 매출이 아니라 카드 기반 관광소비 추정치이므로, 현금·계좌이체 등을 포함한 지역 전체 매출로 해석하지 않는다.
- 따라서 두 값을 단순히 나눠 `1인당 소비액`이라고 표시하지 않는다. 동일 모집단·기간의 분모가 검증된 경우에만 계산한다.
- ML과 정식 대시보드는 `region_code + year_month`가 검증된 행만 결합한다.

### 강남구 ML 예측 (2026-08-28 추가)

- 학습용 표는 `data/processed/ml/11680/monthly_demand.csv`에 재현 가능하게 생성하며, hash 검증 `data/source_snapshots/` 원본만 읽는다. 수동 `data/raw/` 원본은 수정하지 않는다.
- 방문자 목표값은 기존 상단 카드와 동일한 **월간 외지인 순 방문자 수**다. `방문자 수(연인원)`와 혼용하지 않는다.
- 소비 목표값은 카드 기반 **외지인 관광소비액(원)**이다.
- 입력 피처는 예측 시점 이전의 1·3·12개월 전 방문자/소비, 예측 대상 월의 계절성(sin/cos)이다.
- 가장 최근 4개월을 시간순 테스트로 분리해, 전년 동월 seasonal-naive 기준선보다 MAE가 낮은 모델만 저장한다.
- 방문자 수에는 `RandomForestRegressor`, 소비액에는 `LinearRegression`을 선택했다. 상세 평가값은 `artifacts/ml/gangnam_demand_model.metadata.json`에 저장한다.
- 다음 달 업종별 소비 패턴은 업종별 ML 예측이 아니다. 전체 소비액 예측에 최신 관측월 업종 비중을 적용한 **가정 기반 분포**이며 화면에도 표시한다.

## 5. 새 데이터 추가 절차

1. 수동 원본은 `data/raw/`에 그대로 보관하고, 팀 공유폴더·기존 수동 원본은 `data/source_snapshots/`에 hash 검증 복제본으로만 추가한다. 두 경로의 파일 내용은 수정하지 않는다. 활성 ML 카탈로그 경로는 검증이 끝난 snapshot으로 지정한다.
2. 출처 URL, 다운로드일, 기간, 단위, 지역단위, 파일 SHA-256을 source registry 또는 snapshot manifest에 기록한다.
3. CSV 컬럼·인코딩·지역코드·기준월·결측을 확인한 뒤에만 `data/processed/`로 변환한다.
4. 실제 화면 또는 분석에 연결할 때 이 문서의 **현재 실제 연결 상태**와 **Open API 활용 계획**을 갱신한다.
5. 새 Python/Node 라이브러리를 코드에 추가했다면 `requirements.txt` 또는 `frontend/package.json`도 같은 변경에 갱신한다.

### 공식 PDF·세미나 자료의 추가 절차

1. 원문 PDF 사본은 `data/rag/source_documents/`에 변경 없이 저장하고 SHA-256을 기록한다.
2. 발행기관·공식 URL·발행일(모르면 월 단위)·인용 쪽수·사용 제한을 확인한다.
3. 월별 수치표를 복사하지 않고, 정책·운영 방식·지표 해석처럼 기획안에서 검증 가능한 문장만 `official_reference_documents.jsonl`에 요약한다.
4. 원문에 향후 공개 예정·가상 예시·지시문이 있으면 검색 결과에 한계로 기록하고 사실·명령으로 사용하지 않는다.

## 10. 직접 CSV snapshot의 전국 비교층 보강 (2026-09-04)

계양구(`28245`)는 활성 ML에는 등록되어 있었지만, 기존 전국 월별 비교 bundle이 만들어진 뒤에

```text
공식 direct CSV + materialization manifest hash 검증

  → 12개월 비교 context·유사지역 5개 재계산
  → MySQL transaction upsert
```

그 결과 계양구의 2024-01~2026-06 30개월 월별 사실 30건과 원본 파일 출처 18개가 추가되었고,

순 방문자·외지인 소비·숙박 비율·평균 숙박일·체류시간만 30개월 전수 대조했으며, 연인원 방문자와
내국인 소비는 전국 비교 전용 원본 컬럼으로 별도 보존했다. 개별 다운로드 조건 URL은 원본에 없어
`needs_exact_download_url` 상태를 유지한다.
